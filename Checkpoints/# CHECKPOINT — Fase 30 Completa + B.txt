## 3. PATRONES ESTABLECIDOS

### Pattern: Defensive Data Rendering

Cuando un componente recibe data de un query MCP que puede tener propiedades undefined (por mock incompleto o backend parcial):

```tsx
// Arrays: ?? []
{(data.items ?? []).map(...)}

// Numerics: ?? 0
{(data.value ?? 0).toFixed(1)}

// Objects with arrays: check both
if (!data || !data.items || data.items.length === 0) return null;

// Conditional contribution display
{f.contribution != null ? ` · ${f.contribution.toFixed(1)} pts` : ""}
```

**Se aplica en:** todos los sub-componentes de FinanceAnalytics, cualquier componente que reciba data de `useMCPQuery`.

### Pattern: Conditional Section Rendering

```tsx
{ai.cash_flow_forecast && (
  <motion.div variants={motionV.item}>
    <CashFlowSection data={ai.cash_flow_forecast} />
  </motion.div>
)}
```

**Se aplica en:** Reportes AI con múltiples secciones opcionales.

### Pattern: Hook Return for Modal State

```tsx
// In hook:
const [helpOpen, setHelpOpen] = useState(false);
useEffect(() => { /* keyboard listener */ }, []);
return { helpOpen, closeHelp: () => setHelpOpen(false) };

// In layout:
const { helpOpen, closeHelp } = useKeyboardNav();
<KeyboardHelpModal isOpen={helpOpen} onClose={closeHelp} />
```

## ROL ENRIQUECIDO — PLATAFORMA DE ANÁLISIS AI

### Lo que estamos construyendo

Castillo Country Club no es solo un club management platform — es una **super herramienta AI de análisis, toma de decisiones y propuestas estratégicas**. Los agentes MCP no solo consultan datos, los **interpretan, detectan anomalías, proponen acciones y generan reportes ejecutivos**.

### Capas de inteligencia que ya existen:

| Capa | Ejemplo | Fase |
|------|---------|------|
| **Data queries** | `get_financial_summary`, `get_family` | Base |
| **AI Analysis** | `generate_ai_analysis` — health score, cash flow, anomalies | Fase 13 |
| **HITL Approval** | Doble confirmación para acciones críticas | Fase 16-18 |
| **AI Recommendations** | Recomendaciones estratégicas con impacto estimado, confianza, esfuerzo | Fase 13 |
| **Anomaly Detection** | Desviaciones automáticas con severidad y acción sugerida | Fase 13 |
| **Engagement Scoring** | Health score compuesto con factores ponderados | Fase 22 |
| **Risk Assessment** | Concentración de ingresos, HHI, diversificación | Fase 13 |
| **Projection & Forecasting** | Cash flow con intervalos de confianza | Fase 13 |
| **Member Economics** | LTV, CAC, margen por socio, análisis por tier | Fase 13 |
| **AI Chat Widget** | Asistente conversacional con acceso a datos | Fase 19 |

### Cómo seguir proponiendo en futuros chats:

1. **Cada módulo nuevo** debe tener un tab "Análisis AI" si el backend lo soporta
2. **Cada tool nueva** debe considerar: ¿es consulta pura, mutation, o inteligencia?
3. **Las mutations HITL** deben ir siempre a ApprovalQueue
4. **Los reportes AI** deben seguir el patrón de `FinanceAnalytics`: section components, period selector, refresh button
5. **Proponer capabilities** como: predictive alerts, automated reporting, cross-module insights (ej: "Los socios con engagement bajo son los mismos que se atrasan en pagos")

### La visión:

La plataforma conecta **datos operativos** (pagos, reservas, asistencia) con **inteligencia artificial** (análisis predictivo, detección de anomalías, recomendaciones) para que la directiva tome **decisiones informadas** con un click. El protocolo ALWAYS_HUMAN asegura que las acciones críticas siempre pasen por aprobación humana.
