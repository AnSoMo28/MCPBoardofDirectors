## 3. PATRONES ESTABLECIDOS

### Patrón NUEVO: Scatter Plot de Rentabilidad con Cuadrantes

**Cuándo se usa:** Cuando se necesitan visualizar datos en dos dimensiones con segmentación por cuadrantes.

```
1. ScatterChart con XAxis (variable 1) y YAxis (variable 2)
2. Promedio de ambas variables como línea divisoria (ReferenceLine)
3. ReferenceArea coloreados por cuadrante (4 áreas con fillOpacity 0.04)
4. Dots con tamaño proporcional a una tercera variable (custom shape)
5. Click en dot → detail card con métricas + AI insight
6. Quadrant strategy cards con click para filtrar ranking table
7. Ranking: sortable table (desktop) + cards (mobile, Rule #21)
8. HEX constants separados para SVG (QUADRANT_HEX) — no usar CSS vars
```

**Ejemplo:** MemberProfitabilityMatrix.tsx
**Se replica en:** Futuros scatter plots (member engagement vs. activity, revenue vs. satisfaction)

### Patrón NUEVO: Fan Chart (Monte Carlo Percentiles)

**Cuándo se usa:** Cuando se proyectan resultados con incertidumbre y se necesita mostrar la distribución de probabilidad.

```
1. AreaChart con 5 series (P10/P25/P50/P75/P90)
2. P50 como línea principal (strokeWidth 2.5, dots visibles)
3. P25/P75 como líneas secundarias (strokeWidth 1, dash)
4. P10/P90 como líneas extremas (strokeWidth 1, dash largo)
5. Break-even reference line con label
6. Tooltip custom con los 5 percentiles y colores
7. Fan bands como fill (opcional, puede ser complejo)
8. Legend manual (no Recharts Legend) para control preciso
9. GaugeCard para KPIs con progress bar y color thresholds
10. Distribution summary con skewness indicator
```

**Ejemplo:** StressTestPanel.tsx (fan chart + gauge cards + distribution)
**Se replica en:** Futuras proyecciones con incertidumbre (membership forecast, revenue projection)

### Patrón NUEVO: Timeline con Capas Toggleables

**Cuándo se usa:** Cuando hay datos temporales con múltiples dimensiones que el usuario quiere ver por separado.

```
1. Layer toggle chips con Set<string> state (add/remove)
2. BarChart condicional — solo muestra las layers activas
3. Expandible month rows con mini sparkbar + badges
4. Month detail con AnimatePresence open/close
5. Actions panel priorizado (separado del timeline)
6. Season indicator bar horizontal como visual reference
7. Annual summary KPIs como overview
```

**Ejemplo:** SeasonalCalendar.tsx
**Se replica en:** Cualquier vista temporal con múltiples dimensiones (activity timeline, financial history)

### Patrón NUEVO: Scenario Selector con Custom Editor

**Cuándo se usa:** Cuando hay escenarios preconfigurados que el usuario puede modificar o crear desde cero.

```
1. Scenario chips (preconfigured) + "Custom" chip
2. Iteration count selector (buttons, no dropdown)
3. Custom editor visible SOLO cuando "Custom" selected
4. Editor con sliders μ (media) y σ (dispersión) por variable
5. min/max calculados como multiplicador del default
6. Auto-simula al cambiar scenario (useMCPQuery re-fetches)
7. Botón "Ejecutar" para refetch explícito
```

**Ejemplo:** StressTestPanel.tsx
**Se replica en:** Futuros simuladores con presets (event pricing, membership scenarios)

### Patrón CONFIRMADO: Gauge Card con Thresholds

**Cuándo se usa:** Cuando un KPI tiene rangos de bueno/malo.

```
GaugeCard({
  label, value, format, cfg: { goodThreshold, warnThreshold }
})
- format "percent": progress bar + color por threshold
- format "currency": color por threshold (invertido para losses)
- format "month": valor directo con color gold
- Badge decorative con opacity 0.07
```

**Ejemplo:** StressTestPanel.tsx (5 GaugeCards)
**Se replica en:** Cualquier KPI con semáforo

## 4. DECISIONES DE DISEÑO

| # | Decisión | Alternativa descartada | Razón |
|---|---------|----------------------|-------|
| 1 | 6 sub-tabs en FinancialIntelligence (no 7+) | Agrupar "Rentabilidad" dentro de "Briefing" o "Oportunidades" | Las 3 features son herramientas independientes de alto valor. Merecen su propio sub-tab para discoverability |
| 2 | Sub-tab bar con overflow-x-auto | DetailTabs shared component | Sub-tabs son locales al componente, no navegan a rutas diferentes. DetailTabs es para el hub padre |
| 3 | `finance_member_profitability` como auto-load (no on-demand con botón) | Botón "Analizar" explícito | El análisis de rentabilidad es una vista estándar que el admin quiere ver inmediatamente. staleTime 5min evita recalcular |
| 4 | Scatter plot custom shape con circle+text (no dot default de Recharts) | Recharts default dots | Default dots no permiten tamaño proporcional a member_count ni labels de familia. Custom shape da control total |
| 5 | Fan chart con 5 Area lines separadas (no stacked areas) | Stacked areas con fill | Las 5 percentiles son líneas independientes, no acumulativas. Stacked areas crearía visualización incorrecta |
| 6 | Scenario chips como selector (no dropdown) | Dropdown select | 6 escenarios son visibles de una vez como chips. Mejor UX que dropdown escondido |
| 7 | Custom editor con sliders μ y σ separados | Un solo slider por variable | μ (tendencia central) y σ (dispersión) son conceptos estadísticos diferentes. Sliders separados dan control preciso |
| 8 | `SEASON_CONFIG.months` array como reference data (no source of truth) | Que el componente derive season de los months array | La data viene del backend con `season` field por mes. El array es útil para validación y para CR_SEASONALITY knowledge |
| 9 | `TIER_DISPLAY` separado de `BACKEND_TIER_CONFIG` (families/types.ts) | Reutilizar `BACKEND_TIER_CONFIG` directamente | TIER_DISPLAY vive en finance/types.ts para evitar import cross-feature. Pueden divergir en styling |
| 10 | `QUADRANT_HEX` constante separada para SVG | Usar `CHART_PALETTE` directamente | Los quadrants tienen semántica propia (star=emerald, risk=rose). Separarlos hace el código más legible |
| 11 | `SEASON_HEX` constante separada para SVG | Mapear de SEASON_CONFIG | SEASON_CONFIG usa CSS vars. Para SVG/bars se necesitan HEX. Constante separada evita mapeo inline |
| 12 | Actions panel en SeasonalCalendar como sección separada (no inline en timeline) | Mostrar acciones dentro de cada month row | 14 acciones priorizadas son más útiles como lista global ordenada por prioridad que distribuidas en 12 meses |
| 13 | Mini sparkbar en timeline rows (hidden sm:block) | Mostrar siempre el valor numérico | El sparkbar da percepción visual rápida en desktop. En mobile solo se muestra el valor numérico (Rule #21 adapta) |
| 14 | `overflow-x-auto` en sub-tab bar | Wrapping de tabs | 6 tabs necesitan scroll horizontal en mobile. Wrapping rompería la metáfora de barra de tabs |
| 15 | Skeleto diferenciado por componente (3/4/3 skeletons) | Mismo skeleton count para todos | Cada componente tiene densidad diferente. StressTest tiene más secciones que los otros |

## 11. DECISION LOG

| # | Fecha | Decisión | Razón | Impacto |
|---|-------|---------|-------|---------|
| 1 | Mayo 2025 | 3 features nuevas como sub-tabs de FinancialIntelligence (no componentes independientes) | Viven dentro de "Inteligencia" — son herramientas de análisis financiero, no módulos nuevos | Sub-tab bar expande de 3→6. No hay cambios en FinancialDashboard hub |
| 2 | Mayo 2025 | `finance_member_profitability` como auto-load (no on-demand) | El análisis de rentabilidad es una vista estándar. staleTime 5min es suficiente | Diferente al patrón Rule 19 general (on-demand), igual que generate_ai_analysis en Fase 13 |
| 3 | Mayo 2025 | Scatter plot con custom shape (circle+text) en vez de Recharts default dots | Default dots no permiten tamaño proporcional ni labels | Patrón replicable para futuros scatter plots |
| 4 | Mayo 2025 | Fan chart con 5 Area lines separadas (no stacked areas) | Percentiles son líneas independientes, no acumulativas | Las "bandas" de incertidumbre se logran con fillOpacity en los extremos (P10/P90) |
| 5 | Mayo 2025 | Scenario selector con chips (no dropdown) | 6 escenarios visibles de una vez. Mejor UX | Patrón replicable para cualquier selector ≤8 opciones |
| 6 | Mayo 2025 | Custom editor con sliders μ y σ separados | Conceptos estadísticos diferentes. Control preciso para la junta | Solo visible para "Custom" scenario |
| 7 | Mayo 2025 | Actions panel en SeasonalCalendar como sección global priorizada (no inline en months) | 14 acciones ordenadas por prioridad son más útiles como lista global | Separación de concerns: timeline = visualización, actions = recomendaciones |
| 8 | Mayo 2025 | `QUADRANT_HEX`, `FAN_CHART_LINES`, `SEASON_HEX`, `BAR_HEX` como constantes separadas | SVG requiere HEX, no CSS vars. Constantes separadas por feature evitan mapeo inline | No se toca CHART_PALETTE existente |
| 9 | Mayo 2025 | `TIER_DISPLAY` separado de `BACKEND_TIER_CONFIG` | Evita import cross-feature (finance→families). Pueden divergir en styling | Si se unifica, mover a shared config |
| 10 | Mayo 2025 | Sub-tab bar con `overflow-x-auto` + `whitespace-nowrap` | 6 tabs necesitan scroll horizontal en mobile. Wrapping rompe la metáfora | Patrón replicable para 5+ tabs |
| 11 | Mayo 2025 | Skeleto diferenciado por componente (3/4/3) | Cada componente tiene densidad diferente. UX más realista | Mismo patrón: proporcional al contenido esperado |
| 12 | Mayo 2025 | Mock-registry errores documentados pero NO fixeados en esta sesión | Fix requiere ver el archivo completo real. El fix podría romper imports existentes | Se pospone a Fase 14b o 15 con archivo completo |
