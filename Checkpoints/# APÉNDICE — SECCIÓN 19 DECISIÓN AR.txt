**Origen:** Decisión tomada en sesión F39 de reordenar el plan maestro.

## 19.1 — EL RAZONAMIENTO

Se propuso y aprobó la estrategia **"infrastructure-first"**: construir Member 360 y ML Layer ANTES de completar los dominios individuales (Cultural, Age Group, etc.).

```
SIN Member 360 + ML primero:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Cultural Audit → construye su propio member context
  Age Group Audit → construye su propio member context
  Wellness Intel  → construye su propio member context
  Events Intel    → construye su propio member context
  Financial Intel → construye su propio member context
                    ↓
  Después Member 360 → tiene que integrar 5 versiones
  distintas de "member context" → REWORK MASIVO
                    ↓
  Después ML Layer → tiene que limpiar datos de 5
  dominios con formatos distintos → REWORK MASIVO


CON Member 360 + ML primero:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Member 39 → define el ESTÁNDAR de member context
  ML Layer   → define el ESTÁNDAR de prediction pipeline
                    ↓
  Cultural Audit → CONSUME member 360 + PUBLISH al ML layer
  Age Group Audit → CONSUME member 360 + PUBLISH al ML layer
  Wellness Intel  → CONSUME member 360 + PUBLISH al ML layer
  Events Intel    → CONSUME member 360 + PUBLISH al ML layer
                    ↓
  Cada dominio nuevo se ENCHUFA, no construye desde cero
  → CERO REWORK
```

## 19.7 — GANANCIAS vs COSTOS

| | Ganas | Pierdes |
|---|-------|---------|
| **Construir F39+F40 primero** | Foundation sólida, cero rework, cada dominio nuevo se enchufa, predicciones desde día 1 | Velocidad de "dominios completados" baja temporalmente |
| **Construir Cultural+AgeGroup primero** | +2 dominios auditados rápido, checklist visual avanza | Cada uno construye su propio member context, rework después |

**Veredicto: Infrastructure-first es superior.** La deuda técnica de NO hacer Member 360 primero es mucho mayor que el costo de hacerlo ahora.

---

## 19.8 — QUÉ HACE QUE ESTA DECISIÓN SEA DE ARQUITECTO

> "Si construimos Cultural (F34) y Age Group (F35) primero, vamos a tener dos dominios más que funcionan como silos — igual que los que ya tenemos. Pero si construimos Member 360 y ML primero, TODOS los dominios (incluyendo Cultural y Age Group cuando los hagamos) van a tener acceso a una vista unificada y predicciones reales."

**Eso es thinking de arquitecto, no de desarrollador.** Un desarrollador construye features. Un arquitecto construye la infraestructura que hace que las features sean fáciles de construir.
