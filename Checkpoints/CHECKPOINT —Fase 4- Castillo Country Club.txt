═══════════════════════════════════════════════════
PATRONES DE CÓDIGO
═══════════════════════════════════════════════════

Imports: usar @/ alias (configurado en vite.config.ts + tsconfig)
Estilos: Tailwind classes con cn() utility. Variables CSS con var(--color-xxx).
Componentes: forwardRef para inputs/buttons. Props interfaces separadas.
API: callMCPTool(agent, tool, params) → POST /api/agents/{agent}/{tool}
Hooks: useMCPQuery(agent, tool, params) para consultas, useMCPMutation para acciones.
Auth: Zustand persist store con JWT. Roles: SOCIO, STAFF, ADMIN, JUNTA.
Permisos: PermissionGate component + checkPermission() function.
UI exports: todo sale de @/shared/components/ui/index.ts

═══════════════════════════════════════════════════
REGLAS DE ORO (OBLIGATORIAS)
═══════════════════════════════════════════════════

1. CERO DATOS HARDCODEADOS — Toda la data viene del backend via useMCPQuery/useMCPMutation. Los seed data viven en scripts Python del backend. Si el backend no responde, el UI muestra empty state o error — NO fallbacks con datos falsos. Excepción documentada: Sprint 2.

2. CÓDIGO COMPLETO — Nunca crear archivos vacíos ni placeholders de código. Cada archivo se entrega con contenido completo, funcional y production-grade.

3. PREGUNTAR ANTES DE ASUMIR — Siempre confirmar qué tiene el usuario antes de crear algo que podría ya existir o duplicar.

4. ENTREGA EN BLOQUES — Máximo 3-4 archivos por bloque. Usuario confirma "listo" antes de pasar al siguiente. Sin loops, sin repetir.

5. ROUTER AL FINAL — Las rutas nuevas se entregan en el último bloque de cada sprint, no intercaladas.

6. FONT FAMILIES DEL SISTEMA — Usar siempre var(--font-display), var(--font-ui), var(--font-mono). Nunca Inter, Roboto, Arial.

7. ACCESIBILIDAD — Botones mínimo 48x48px. Body text mínimo 16px. WCAG AA. Aria labels. Focus outlines.

8. ANIMACIONES — Framer Motion para entradas, transiciones de tab, staggered reveals. CSS transitions para hover states. Siempre choreografiado, nunca caótico.

9. RESPONSIVE — Desktop table + mobile card list. Grid responsive con breakpoints sm/md/lg.

10. ESTADOS — Siempre manejar loading (skeleton), error (mensaje + acción), y empty state (icono + mensaje + acción opcional).
