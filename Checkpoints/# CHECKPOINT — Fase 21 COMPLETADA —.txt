2. **Explica** — AI genera narrativas personalizadas con causa raíz y benchmarks reales de Costa Rica

### Patrón: Advisor Action Bridge (NUEVO F21)

**Concepto:** Cada insight opcionalmente tiene un `action?: AdvisorAction` tipado. El banner renderiza "Ejecutar" condicionalmente. El shell maneja la mutation con loading/feedback. HITL usa modal de confirmación.

**Flujo:**
```
1. Insight tiene action → Banner muestra "Ejecutar" (primary, Zap icon)
2. User click → onExecute(insightId)
3. Shell resuelve: insight.action.approvalLevel === "auto"?
   YES → mutation.mutateAsync(params) → toast → cache invalidation
   NO → setModalInsight(insight) → <AdvisorActionModal />
4. Modal muestra: title, reasoning, riskSummary, estimatedImpact, server.tool
5. User "Confirmar ejecución" → handleModalConfirm → mutation → toast
6. actionStates[insightId] = "done" → botón cambia a checkmark "Listo"
7. Cache invalidado → queries refetch → Advisor re-computa → insight desaparece o cambia
```

**Firma del callback:**
```typescript
onExecute?: (insightId: string) => Promise<void>
```

## 14. DECISION LOG

| Fecha | Decisión | Razón | Impacto |
|-------|---------|-------|---------|
| Jun 2026 | `useMCPMutation` co-located en `useMCPQuery.ts` — no existe como archivo separado | El checkpoint anterior lo referenciaba mal. Leer archivo real. | No crear archivo nuevo para mutations |
| Jun 2026 | Banner "tonto" con `onExecute: (insightId) => Promise<void>` | Banner no sabe de mutations. Shell mapea insightId → mutation. Desacopla testing y composición. | 3 banners + 3 shells |
| Jun 2026 | Sección "Acciones Disponibles" consolidada en GlobalAdvisorBanner | 5 de 25 insights con action — demasiado ruido si cada uno tiene botón individual. Finance (3/18) y Events (3/15) son manejables con botones individuales. | Global banner layout |
| Jun 2026 | AdvisorAction SOLO type "mutate" — NO unificar navigate | Los 3 banners manejan navegación diferente (rutas, tabs, fechas, eventos). Refactorizar es scope creep para F21. Coexisten campos legacy + action. | Unificación a F22 |
| Jun 2026 | AIInsightNarrative inline (expandible) | 2-3s inline es aceptable. Panel lateral rompe flujo visual. Skeleton shimmer como loading. | UX del Advisor |
| Jun 2026 | AISimulationPanel toggle por insight strategy | Simulación es contextual al insight. Tab separada pierde contexto. | 3 escenarios inline |
| Jun 2026 | Board Brief via PDF (print window) | Usuario pidió PDF. Print window más limpio que librería PDF. CSS profesional para documento. | Output format |
| Jun 2026 | Advisor Chat como extensión de AIChatWidget existente | AIChatWidget ya existe. `advisorContext` prop activa Advisor mode. No crear componente nuevo. | Chat integration |
| Jun 2026 | 5 AI tools como AUTO approval | Tools de análisis no tienen side effects. Output es draft — usuario decide si distribuir. | Approval levels |
| Jun 2026 | `generate_json` con triple fallback de parsing | Claude frecuentemente envuelve JSON en ```json blocks. Triple fallback evita errores. | Backend robustez |
| Jun 2026 | Card structure: outer div (border) + inner flex (badge+content+action) + narrative full-width debajo | Narrative necesita full-width debajo del flex row. Sin esto, layout se rompe. Corregido después de bug. | 3 banners |
| Jun 2026 | Brief result state en ExecutiveDashboard (local) | Brief es contextual al dashboard. Estado local más simple que estado global. | State management |
| Jun 2026 | AdvisorChatContext construction desde globalInsights en shell | Shell filtra y formata. Chat widget no necesita saber del Advisor hook. | Desacoplamiento |
| Jun 2026 | F21 dividido en F21a + F21b | ~2,650 líneas es mucho para un bloque. F21a = backend + action bridge. F21b = AI UI layer. | Workflow |
