# Fase 36: Cultural & Social Module — Propuesta de Diseño

---

## 1. Visión de Producto

El Castillo Country Club no es un resort genérico. Es un club de campo premium en Costa Rica con identidad cultural fuerte. **El módulo Cultural & Social es el corazón de esa identidad.**

No es "un calendario de eventos más." Es el motor que:
- **Organiza la vida cultural del club** — galas, exposiciones, programas estacionales
- **Gestiona el entretenimiento premium** — artistas, DJs, bandas, comediantes
- **Representa la marca Castillo** — formalidad, elegancia, curaduría
- **Protege al club con HITL** — presupuestos de gala y contratos de artistas requieren aprobación

---

## 2. Arquitectura del Módulo

### 2.1 Estructura de archivos

```
features/cultural/
├── types.ts
├── CulturalDashboard.tsx          ← Hub con DetailTabs
└── components/
    ├── CulturalCalendar.tsx       ← Tab 1: Vista unificada
    ├── GalasPanel.tsx             ← Tab 2: Galas y eventos formales
    ├── ProgramsPanel.tsx          ← Tab 3: Programas culturales
    ├── EntertainmentPanel.tsx     ← Tab 4: Actos de entretenimiento
    ├── ExhibitionsPanel.tsx       ← Tab 5: Exposiciones de arte
    ├── GalaFormModal.tsx          ← Modal HITL para crear gala
    ├── EntertainmentFormModal.tsx ← Modal HITL para contratar artista
    └── ProgramFormModal.tsx       ← Modal HITL para crear programa
```

### 2.2 Patrón de arquitectura

Siguiendo el patrón establecido por OperationsDashboard y CommunicationCenter:

```
CulturalDashboard (hub)
├── CulturalCalendar    → get_cultural_calendar (AUTO, staleTime 120s)
├── GalasPanel         → manage_social_events filter type=gala (AUTO) + organize_formal_gala (HITL)
├── ProgramsPanel      → manage_cultural_program (AUTO list + HITL create)
├── EntertainmentPanel → manage_entertainment_acts (AUTO list/get + HITL create)
└── ExhibitionsPanel   → manage_art_exhibitions (AUTO CRUD)
```

**Lazy loading** con `Suspense` — igual que OperationsDashboard.
**Cada tab** se carga on-demand cuando el usuario hace click.

### 2.3 MCP Tools mapping

| Tool | Server | Approval | Frontend feature | Pattern |
|------|--------|----------|-----------------|---------|
| `organize_formal_gala` | `cultural_social` | 🔴 HITL | GalasPanel + GalaFormModal | Submit → pending_approval → ApprovalQueue |
| `manage_entertainment_acts` | `cultural_social` | 🔴 HITL (create) / 🟢 AUTO (list, get, update_status) | EntertainmentPanel | List auto-load + create via modal HITL |
| `manage_cultural_program` | `cultural_social` | 🔴 HITL (create) / 🟢 AUTO (list, get, update_status) | ProgramsPanel | List auto-load + create via modal HITL |
| `manage_social_events` | `cultural_social` | 🟢 AUTO (full CRUD) | GalasPanel (eventos no-gala) | Auto-load, inline create/edit |
| `manage_art_exhibitions` | `cultural_social` | 🟢 AUTO (full CRUD) | ExhibitionsPanel | Auto-load, inline create |
| `get_cultural_calendar` | `cultural_social` | 🟢 AUTO | CulturalCalendar | Auto-load, staleTime 120s |

## 5. Design Patterns — Lo que hace especial este módulo

### 5.1 Visual identity por tipo de evento

Cada tipo de evento cultural tiene una identidad visual distinta usando tokens del Silver Tide:

| Tipo | Ícono | Color token | Glow |
|------|-------|-------------|------|
| Gala formal | 🎭 Theater | `gold-400` | Gold aura |
| Evento social | 🍷 Wine | `terracotta-400` | Warm glow |
| Programa cultural | 🎵 Music | `teal-400` | Teal accent |
| Entretenimiento | 🎸 Guitar | `emerald-400` | Emerald pulse |
| Exposición | 🖼️ Frame | `sage-400` | Sage subtle |

Esto se implementa como config maps (igual que `CHANNEL_CONFIG` en CommunicationCenter).

### 5.2 HITL como feature, no como bloqueo

Cuando un staff crea una gala, el flujo NO se siente como "tu request fue bloqueado." Se siente como "tu gala está siendo revisada por el director — te avisamos." El feedback visual:

1. `showToast({ type: "success", message: "Gala 'Noche Invernal' enviada a aprobación" })`
2. La gala aparece en estado "Pendiente" con badge dorado
3. En ApprovalQueue el admin ve el resumen con presupuesto y riesgo

### 5.3 AI insights por tab (Nivel 1 — auto-load)

Cada tab incluye un insight contextual que viene del backend como parte de la response. No es un tool AI separado — es un campo `ai_insight` en la response del tool principal. Esto es más eficiente que hacer dos queries.

**Patrón:** Igual que DailyBriefing (`data.ai_insight`) y ComplianceCheck (`data.ai_summary`).
