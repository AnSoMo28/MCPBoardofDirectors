## 3. PATRONES ESTABLECIDOS

### Patrón: Auto-load Context + On-demand Intelligence

Creado en esta sesión para SmartSchedule y verificado en ComplianceCheck.

```
┌──────────────────────────────────────────────────────────┐
│  LAYER 0 — Auto-Load Context (siempre visible)          │
│  Queries con staleTime > 0 que cargan al mount          │
│  → get_facility_occupancy (staleTime: 120s)             │
│  → get_maintenance_schedule (staleTime: 300s)           │
│  → compliance_report_generate (staleTime: 300s)         │
│  → compliance_alert_list (staleTime: 300s)              │
│  → Proporcionan CONTEXTO para todo lo demás             │
├──────────────────────────────────────────────────────────┤
│  LAYER 1 — On-Demand Cross-Agent (CTA explícito)        │
│  Queries con enabled: shouldFetch                       │
│  → event_get_calendar (date-scoped)                     │
│  → detect_scheduling_conflicts (date-scoped)            │
│  → detect_anomalies (scope-agnostic)                    │
│  → Usuario controla cuándo se ejecuta                   │
├──────────────────────────────────────────────────────────┤
│  LAYER 2 — Client-Side Intelligence (instant)           │
│  Recommendation engine computa de data ya cargada       │
│  → generateScheduleRecommendations()                    │
│  → generateComplianceRecommendations()                  │
│  → 0ms latency, 0 network calls                         │
│  → Narrativa + reglas priorizadas + acciones            │
├──────────────────────────────────────────────────────────┤
│  LAYER 3 — Deep Insights (on-demand CTA)                │
│  Queries con enabled: showDeepInsights                  │
│  → generate_quarterly_insights                          │
│  → 3-columnas: Logros / Mejoras / Estratégicas          │
│  → Stats bar + colapsable                               │
└──────────────────────────────────────────────────────────┘
```

**Cuándo se aplica**: Cada componente de dashboard que necesita mostrar contexto + inteligencia.
**Dónde se replica**: DailyBriefing (B1-B4), ComplianceCheck (C1-C3), SmartSchedule (S1-S4).

### Patrón: Cross-Agent Self-Query

Creado cuando un componente on-demand (como `AIScheduleAdvisor`) necesita datos de múltiples agentes que ya fueron cargados por otros sub-componentes.

```typescript
// Advisor hace sus propias queries
const eventsQ = useMCPQuery("events", "event_get_calendar", params, { enabled: shouldAnalyze });
const conflictsQ = useMCPQuery("proactive_recommendation", "detect_scheduling_conflicts", params, { enabled: shouldAnalyze });

// Si S2/S3 ya cargaron la misma data, React Query sirve cached result
// Mismo query key = mismo agent + tool + params = cache hit
// Sin llamadas redundantes de red
```

### Patrón: Date-Scoped Cross-Agent Query

```typescript
// Componente recibe `date` del padre y calcula un range contextual
const dateRange = { date_from: date-1, date_to: date+1 };

// Query usa ese range para buscar contexto
useMCPQuery("events", "event_get_calendar", { date_from, date_to }, { enabled: shouldFetch });

// Filtra por el día exacto del padre
const selectedDay = calData.data.find(d => d.date === date);
```

## 4. DECISIONES DE DISEÑO

| # | Decisión | Alternativa descartada | Razón |
|---|---------|----------------------|-------|
| 1 | **Mantener CTA "Generar" en SmartSchedule** en vez de auto-load todo | Auto-load completo | El date picker requiere input del usuario; facility y maintenance son auto-load pero el análisis de eventos/conflicts es date-specific |
| 2 | **Mantener timeline visual** en SmartSchedule | Simplificar a lista | El timeline es diferenciador visual, solo necesitaba alimentarse con datos reales |
| 3 | **Mantener utilization charts** con datos derivados de occupancy | Eliminar charts | Los charts están bien construidos, solo necesitan data real de `get_facility_occupancy` |
| 4 | **2 cross-agents** en SmartSchedule (event_calendar + detect_scheduling_conflicts) | Solo event_calendar | Ambos son el core value de "Smart"Schedule — sin conflictos no hay inteligencia |
| 5 | **Quick actions con showToast** | Solo lectura | Los showToast dan acceso rápido y preparan para mutations futuras |
| 6 | **Usar tipos de `recommendations/types.ts`** como source of truth | Crear tipos paralelos en contracts.ts | Los tipos ya existían con field names alineados al backend Python. Re-exportar evita duplicación |
| 7 | **Self-contained queries en AIScheduleAdvisor** | Recibir events/conflicts como props del padre | Más desacoplado; React Query cache evita llamadas redundantes |
| 8 | **ConflictSeverity enum import** como value import | Strings literales | El enum ya existe con los valores correctos |
