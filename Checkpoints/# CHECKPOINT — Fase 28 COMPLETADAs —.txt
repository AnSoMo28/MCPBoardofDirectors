## 4. PATRONES ESTABLECIDOS / ACTUALIZADOS

### Patrón NUEVO: Communication Advisor Pattern (F28)

**Concepto:** 8 rules × 2 layers (macro health + micro performance) como hook client-side con Advisor Banner.

**Niveles:**
```
Layer 1 — Macro (Communication Health):
  R1: delivery_critical (< 70%) → HIGH
  R2: health_score (< 40 critical, < 60 medium) → CRITICAL/MEDIUM
  R3: channel_diversity (< 2 channels) → HIGH
  R4: failure_rate (> 6% high, > 3% medium) → HIGH/MEDIUM

Layer 2 — Micro (Performance):
  R5: comms_gap_7d (0 comms in 7 days) → HIGH
  R6: whatsapp_underused (< 10%) → MEDIUM
  R7: personalization_low (< 15%) → MEDIUM
  R8: upcoming_active (> 0 queued) → INFO (positive)
```

**Patrón:** `useCommunicationAdvisor(analytics, history, scheduled)` → `CommunicationAdvisorInsight[]` → `CommunicationAdvisorBanner`

**Cuándo se aplica:** Communication domain.
**Archivos:** `hooks/useCommunicationAdvisor.ts`, `components/CommunicationAdvisorBanner.tsx`
**Replaces:** `computeInsights()` function + `InsightCard` component inline en Overview

### Patrón NUEVO: RAG Grounding for Domain Agents (F28)

**Concepto:** Domain agent invoca RAG engine para fundamentar recomendaciones con documentación real del club.

**Niveles:**
```
DomainAgent._enrich_with_rag_context(query, max_results)
  → rag_service.search_documents(query, max_results, access_level)
  → [{source, content, score}] or [] if unavailable
Agent enriches recommendations with citations
  → "Según [policy doc]: [relevant excerpt]..."
```

**Patrón defensivo:** RAG es optional. Si no disponible, agent funciona igual sin citations. `try/except` con `logger.warning`.

**Cuándo se aplica:** Cualquier domain agent con `rag_service` inyectado.
**Archivos:** `communication_agent.py` (F28). Futuro: Finance, Events.
**Patrón:** P29

### Patrón NUEVO: Emergency Cross-Agent Escalation (F28)

**Concepto:** Emergency broadcast detecta keywords y sugiere acciones derivadas de otros agents.

**Keywords:**
- "evacuación" → facility closure + event cancellation + board notification
- "clima/tormenta" → facility closure + event postponement + board notification
- "seguridad" → facility lockdown + event evaluation + board notification
- "salud" → wellness alert + board notification
- "infraestructura" → maintenance alert + facility status

**Response:** `suggested_actions[]` con server, tool, params, reasoning, auto_executable.

**Cuándo se aplica:** `manage_emergency_broadcast` tool.
**Archivos:** `communication_agent.py` `_get_emergency_suggested_actions()`.
