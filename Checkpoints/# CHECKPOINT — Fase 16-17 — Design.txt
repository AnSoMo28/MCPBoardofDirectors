## 3. PATRONES ESTABLECIDOS

### Patrón: AI Family Intelligence (NUEVO en Fase 17)

**Arquitectura de 4 herramientas AI on-demand para el módulo de familias:**

```
┌─────────────────────────────────────────────────────────┐
│            FamilyIntelligencePanel.tsx                   │
│  4 secciones independientes, cada una con:              │
│  1. Botón trigger ("Analizar")                          │
│  2. useMCPQuery con enabled: false                      │
│  3. onClick → setEnabled(true) → query dispara          │
│  4. Loading: Skeleton                                   │
│  5. Error: EmptyState con retry                         │
│  6. Success: Cards con tone contextual                  │
│                                                         │
│  ┌──────────────────┐  ┌──────────────────┐            │
│  │  Churn Prediction │  │ Activity Recs    │            │
│  │  tone="rose"      │  │ tone="emerald"   │            │
│  │  ScoreGauge SVG   │  │ Match bars       │            │
│  │  Factor bars      │  │ Scheduling       │            │
│  │  AI Recommendation│  │ Target members   │            │
│  └──────────────────┘  └──────────────────┘            │
│  ┌──────────────────┐  ┌──────────────────┐            │
│  │  Social Matches   │  │ Engagement Plan  │            │
│  │  tone="teal"      │  │ tone="gold"      │            │
│  │  Match cards      │  │ ScoreGauge SVG   │            │
│  │  Interests badges │  │ Actual → Objetivo│            │
│  │  Suggested act.   │  │ Actions timeline │            │
│  └──────────────────┘  │ ROI estimado     │            │
│                         └──────────────────┘            │
└─────────────────────────────────────────────────────────┘
```

**Niveles de carga:**
- Nivel 1 (auto-load): Datos estáticos — NO se usa en AI panel
- **Nivel 2 (on-demand): Inteligencia — PATRÓN APLICADO aquí**
  - `enabled: false` inicial
  - Botón "Analizar" → `setEnabled(true)`
  - `staleTime: 0` — siempre refetch (resultados AI pueden variar)
  - Regla #19: SIEMPRE botón, NUNCA auto-load
- Nivel 3 (two-phase): Dos triggers separados — no se necesita aquí

**Approval levels decision:**
| Tool | Approval | Razón |
|------|----------|-------|
| `family_predict_churn` | AUTO | Solo lectura, análisis sin side effects |
| `family_recommend_activities` | AUTO | Sugerencias sin compromiso |
| `family_social_match` | AUTO | Matching sin notificar a la otra familia |
| `family_engagement_plan` | SEMI | Genera plan de acción → admin debe estar al tanto para follow-through |

**Replicable a otros módulos:**
- Fase 18 (Events): `event_predict_attendance`, `event_recommend_optimization`, `event_conflict_resolution`, `event_engagement_boost`
- Finance: `finance_predict_seasonal`, `finance_recommend_cost_optimization`, `finance_risk_scenarios`
- Wellness: `wellness_predict_risk`, `wellness_recommend_personalized_plan`

      return;

});

| # | Decisión | Alternativa descartada | Razón |
|---|---------|----------------------|-------|
| D1 | Tab "Análisis AI" en vez de "Inteligencia" o "AI Insights" | "Inteligencia", "AI", "Insights" | Más descriptivo y profesional para un club de montaña de alto nivel |

| D4 | SocialGraph: tooltip HTML overlay (no Canvas tooltip) | Canvas-rendered tooltip | HTML permite badges, links, scroll, responsive. Canvas tooltip es limitado. |
| D5 | SocialGraph: nodos sugeridos en anillo exterior (1.4x) | Mismo anillo con dashed border | Separación visual clara: conexiones reales vs sugerencias AI. Anillo exterior = "no confirmado". |
| D6 | PreferencesTab en vez de modal | Modal overlay | Más espacio para formularios, consistente con otros tabs del detail |
| D7 | Toggle buttons para channels/interests en vez de checkboxes | Checkbox list | Más touch-friendly (min-h-44px), visualmente premium, Silver Tide aesthetic |
| D8 | `staleTime: 0` en AI tools | staleTime normal (60-300s) | Resultados AI pueden variar — siempre refetch al re-trigger |
| D9 | ConnectionsTab self-fetching en vez de recibir prop | Prop drilling desde parent | Eliminación de dependencia de `get_family` response shape. Social graph es tool separada. |

| D12 | `ScoreGauge` como componente local (no shared) | Extraer a shared/ui | Solo se usa en FamilyIntelligencePanel y FinanceOverview. Si se reutiliza más, se mueve después. |
| D13 | Factory `fm()` helper para FamilyMember en list mock | Repetir objeto completo 8 veces | DRY — helper reutilizable que produce FamilyMember mínimo |
| D14 | `createMockFamilyCreate()` devuelve `pending_approval` | Devolver success directo | Simula el comportamiento real del backend HITL. Testing del flujo completo. |
| D15 | Mock data costarricense en todos los factories | Datos genéricos | Consistencia con la identidad del proyecto: Castillo Country Club, Costa Rica |

### Architecture

```tsx

### Sección: HITL Flow Pattern — AGREGAR

```markdown
## HITL Flow Pattern (Fase 17)

When mutation tool has HITL approval:
1. Backend returns { status: "pending_approval", request_id: "..." }
2. Frontend shows showToast({ type: "info", message: "Solicitud enviada..." })
3. Navigate back to list page (not stay in form)
4. ApprovalQueue shows the pending request
5. After approval, backend calls execute_create/update internally

Example (FamilyForm):
const createFamily = useMCPMutation(server, tool, {
  onSuccess: (data) => {
    if (data?.data?.status === "pending_approval") {
      showToast({ type: "info", message: "Pendiente de aprobación" });
      navigate("/admin/families");
      return;
    }
    showToast({ type: "success", message: "Creado" });
    navigate(`/admin/families/${data.data.id}`);
  },
});
```

| Jun 2025 | FamilyForm: navigate a lista en vez de stay con pending state | HITL flow es: submit → showToast info → navigate lista → ApprovalQueue muestra pending | UX más limpia — ApprovalQueue es source of truth para pending requests |
