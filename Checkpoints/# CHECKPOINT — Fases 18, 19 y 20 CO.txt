## 3. PATRONES ESTABLECIDOS

### Patrón: Client-Side AI Advisor (creado F17, replicado F18-F20)

**Concepto:** Hook de React que computa insights estratégicos de datos ya en cache de React Query. Cero llamadas al backend. Cero latencia. Aparece como banner en el top del dashboard.

**Niveles:**
```
Nivel 0: Shell queries (pre-warming, staleTime)
   ↓ datos en caché
Nivel 1: useXxxAdvisor(datos de cache) → AdvisorInsight[]
   ↓ N reglas computacionales
Nivel 2: <XxxAdvisorBanner /> → render condicional (solo si hay insights)
   ↓ click "Ir"
Nivel 3: setActiveTab(targetTab) / navigate(route) → navega al destino
```

**Implementaciones:**
| Fase | Advisor | Reglas | Capas | Fuente |
|------|---------|--------|-------|--------|
| F17 | useRecommendationAdvisor | 7 | 1 | proactive_recommendation cache |
| F18 | useFinancialAdvisor | 18 | 3 (macro/micro/fusion) | finance cache |
| F19 | useEventAdvisor | 15 | 3 (macro/micro/fusion) | events cache |
| F20 | useGlobalAdvisor | 25 | 5 (diagnostic/strategy/prediction/innovation/execution) | cross-agent cache |

**Cuándo se aplica:** Cualquier dashboard que tiene múltiples queries de diferentes dominios donde los datos ya cargados pueden cruzarse para producir insights.

**Fases futuras donde se replica:**
- F21: Se agrega "Action Bridge" — los insights se conectan a mutations reales
- F22: Polish — se consolida tipado, se limpia duplicación

### Patrón: CRUD con Action Routing (pre-existente, documentado F17)

Tools que soportan múltiples operaciones bajo un solo nombre, diferenciadas por param `action`:
```typescript
useMCPQuery("events", "event_manage_rsvps", { action: "list", event_id })
useMCPMutation("events", "event_manage_rsvps", { action: "add", event_id, family_id })
```
Usado por: events (event_manage_rsvps, event_coordinate_vendors), families.

### Patrón: Pre-warming Queries en Shell

```typescript
// En el shell del dashboard, queries duplicadas para pre-calentar cache:
const aiQ = useMCPQuery("finance", "generate_ai_analysis", { period }, { staleTime: 300_000 });
// React Query deduplica — las mismas queries en sub-componentes cargan al instante desde cache
```
Aplicado en: FinancialDashboard (F18), ExecutiveDashboard (F20).

## 4. DECISIONES DE DISEÑO

| Decisión | Alternativa descartada | Razón |
|----------|----------------------|-------|
| Advisor como hook + banner inline en shell | Tab separada de "AI Advisor" | Un tab más sería 8vo tab. Advisor tiene sentido como contexto global |
| 3 capas de inteligencia (macro/micro/fusion) en F18/F19 | Una sola capa plana | Diferentes niveles de profundidad permiten priorización mejor |
| Global Advisor con 5 capas (diagnostic/strategy/prediction/innovation/execution) | Solo diagnóstico + ejecución | Las capas intermedias (estrategia, predicción, innovación) son el diferenciador vs software tradicional |
| Advisor consume cache (queries duplicadas en shell) | Advisor hace sus propias queries | React Query deduplica. Shell pre-calienta, sub-componentes cargan al instante |
| Advisor defensivo (funciona con datos parciales) | Forzar queries de todos los dominios | Usuario puede no haber visitado Finance/Events. No bloquea, computa con lo disponible |
| Systemic Risk Score compuesto (F20) | Health Score de un solo dominio | Combina health + anomalies + conflicts + approvals en un solo número |
| Competitive Benchmark Simulation hardcodeado | Benchmarks desde backend | CR private clubs data no existe como API. Hardcodear benchmarks locales es práctico |
| TODO placeholders en ExecutiveDashboard para cache connections | Conectar todo inmediatamente | F21 conectará useGlobalStatus. No bloquea F20, permite iteración |
| Keyframes consolidados en shells pero mantenidos en sub-componentes | Eliminar de sub-componentes | Sub-componentes pueden montarse independientemente. Limpieza definitiva en F22 |
| Sub-componentes NO se re-escribieron en F18 | Re-escritura completa | Están bien construidos. Solo necesitan fixes quirúrgicos |

## 8. LA VISIÓN DE IA — Cómo estamos construyendo una herramienta de decisión inteligente

### El problema que resolvemos

La mayoría del software de gestión de clubes es **un repositorio de datos** — te muestra lo que pasó. Nuestro sistema es un **sistema de decisión** — te dice qué hacer, por qué, y te deja ejecutar con un clic.

### Los 5 niveles de inteligencia

```
NIVEL 1: DATOS (F1-F7)
├── Queries al backend
├── Visualización de KPIs
├── Charts y tablas
└── "¿Qué está pasando?"

NIVEL 2: CONTEXTO (F8-F15)
├── Auto-load + staleTime optimization
├── On-demand sections (CTA → loading → results)
├── Types source of truth (backend 1:1)
└── "¿Qué necesito ver ahora?"

NIVEL 3: INTELIGENCIA CLIENT-SIDE (F16-F19)
├── AI Advisors domain-specific (Financial, Event, Recommendations)
├── Reglas computacionales de 7-18 factores por dominio
├── Cross-domain analysis within single agent
├── Impact scoring (high/medium/low)
├── Confidence scoring (0-100)
├── 0 API calls, 0 tokens, 0ms
└── "¿Qué debería hacer y por qué?"

NIVEL 4: CROSS-AGENT INTELLIGENCE (F20)
├── Global Advisor (25 reglas, 5 capas)
├── Diagnostic → Strategy → Prediction → Innovation → Execution
├── Systemic Risk Score compuesto
├── Cross-domain fusion (finance × events × members × operations)
├── Competitive benchmarks (CR private clubs)
├── "¿Qué no estoy viendo que otros clubes sí hacen?"
└── "¿Qué va a pasar en 90 días si no actúo?"

NIVEL 5: ACCIÓN INTELIGENTE (F21 — el futuro)
├── Pre-filled mutation params desde Advisor insights
├── One-click execute: Advisor → Mutation → HITL → Done
├── Batch actions: "Aprobar todas las de bajo riesgo"
├── AI-generated communication drafts
├── Weekly Action Plan ejecutable
└── "Ejecutá esto, ya lo analicé"
```

### Lo que hace único a nuestro sistema

| Característica | Software tradicional | Nuestro sistema |
|---------------|---------------------|-----------------|
| Datos | Tablas y charts | Tablas, charts + Advisor que interpreta |
| Análisis | El usuario analiza | El sistema analiza y propone con 65 reglas |
| Decisiones | El usuario decide qué mirar | El sistema prioriza por impacto y confianza |
| Acciones | El usuario navega forms | El sistema ejecuta con un clic (F21) |
| Cross-domain | Cada módulo es aislado | Global Advisor cruza TODOS los dominios |
| Inteligencia | Backend ML (latencia, tokens) | Client-side compute (0ms, 0 tokens) |
| Predicción | No existe | 90-day trajectory, churn prediction, demand forecast |
| Innovación | No existe | Hidden revenue, cross-sell, partnership, benchmark |
| Ejecución | Manual | Weekly plan, board brief, scenario test |
| Personalización | Genérico para todos | Basado en datos reales del club específico |
