## 3. PATRONES ESTABLECIDOS

### Patrón NUEVO: Composite Health Score (Multi-Dimension Weighted)

**Cuándo se usa:** Cuando se necesita un score compuesto de múltiples dimensiones con ponderaciones diferentes.

```
1. Modelo: 5 dimensiones con pesos (30/25/20/15/10)
2. Score por familia: 0-100 calculado como weighted sum
3. Gauge radial (PieChart custom) para score general
4. Radar chart para comparar dimensiones (actual vs anterior)
5. Distribution histogram para ver dispersión
6. Trend AreaChart con min/avg/max bands
7. At-risk table/cards con delta, dimensión débil, acción sugerida
8. Factor importance bars para explicar qué pesa más
```

**Implementación:** MemberHealthScore.tsx
**Se replica en:** Wellness health score, operational health score, cualquier modelo compuesto

### Patrón NUEVO: Behavioral Micro-Segmentation

**Cuándo se usa:** Cuando se necesita segmentar usuarios en clusters naturales basados en comportamiento.

```
1. Treemap (custom SVG cell) para distribución visual
2. Segment Cards con métricas clave y trend
3. Persona Profiles expandibles (motivations, pain points, best channel)
4. Migration Heatmap (desktop table + mobile list, Rule #21)
5. Revenue/Value breakdown por segment (stacked bar)
6. Campaign Readiness (horizontal bars con best channel)
7. Segment Stability Index (progress bar)
```

**Implementación:** MemberSegmentation.tsx
**Se replica en:** Engagement segmentation, event attendee segmentation, cualquier clustering

### Patrón NUEVO: Monte Carlo Fan Chart

**Cuándo se usa:** Cuando se necesita mostrar proyecciones con incertidumbre (rangos percentiles).

```
1. 5 bands stacked: floor (invisible) + P10-P25 + P25-P50 + P50-P75 + P75-P90
2. P50 center line separada (LineChart superpuesto)
3. Custom FanTooltip mostrando 5 percentiles
4. Y domain calculado con padding automático
5. XAxis con formato de mes (tickFormatter)
```

**Implementación:** MemberLTV.tsx
**Se replica en:** Cualquier proyección con bandas de confianza (financial forecasting, demand prediction)

### Patrón NUEVO: LTV × Risk Scatter Matrix

**Cuándo se usa:** Cuando se necesita visualizar familias/entidades en 2 dimensiones con cuadrantes de prioridad.

```
1. ScatterChart con X = risk metric, Y = value metric
2. ZAxis para sizing (bubble size = value)
3. ReferenceLine vertical/horizontal para cuadrantes
4. Text SVG posicionado para etiquetas de cuadrante
5. Scatter agrupado por categoría (tier/segment) con colors diferentes
6. Custom tooltip con datos completos de la entidad
```

**Implementación:** MemberLTV.tsx
**Se replica en:** Cualquier análisis de priorización 2D (profitability matrix ya existe, esto es el patrón generalizado)

### Patrón NUEVO: Sensitivity Tornado

**Cuándo se usa:** Cuando se necesita mostrar qué factores impactan más un outcome.

```
1. BarChart horizontal (layout="vertical")
2. Data sorted por absolute impact (mayor → menor)
3. Cell colors: positive = emerald, negative = rose
4. FillOpacity escalado por magnitud del impacto
5. XAxis con +/- formatter
```

**Implementación:** MemberLTV.tsx
**Se replica en:** Scenario analysis, budget impact, cualquier sensitivity analysis

### Patrón NUEVO: Intervention Playbook (Expandible)

**Cuándo se usa:** Cuando se tiene un set de acciones/estrategias con metadata detallada.

```
1. Cards expandibles con nombre, success rate, cost, ROI en header
2. Expandible: description completa, best_for_segments, best_for_risk_factors
3. Footer con timeline + effort badge (color-coded)
4. Click → setExpandedIntervention pattern
```

**Implementación:** MemberChurnPrevention.tsx
**Se replica en:** Campaign playbook, maintenance playbook, cualquier library de acciones

### Patrón NUEVO: Cost of Inaction Banner

**Cuándo se usa:** Cuando hay un costo cuantificable por NO actuar.

```
1. Banner full-width con AlertTriangle icon
2. Texto con "Costo de inacción: ₡XX" formateado
3. Subtexto con ROI de intervenir (inaction_cost / recommended_budget)
4. ExportButton al lado derecho
```

**Implementación:** MemberChurnPrevention.tsx
**Se replica en:** Cualquier módulo donde inaction tiene costo (aging accounts, compliance, maintenance)

## 4. DECISIONES DE DISEÑO

| # | Decisión | Alternativa descartada | Razón |
|---|---------|----------------------|-------|
| 1 | Módulo independiente `features/members/` | Sub-tab en Engagement o Finance | Member Intelligence alimenta 3 módulos diferentes — necesita ser hub autónomo |
| 2 | 4 tabs: Health, Segmentation, LTV, Churn | 6+ tabs con más granularidad | 4 tabs es el sweet spot — suficiente profundidad sin overwhelm |
| 3 | Health Score auto-load, Segmentation auto-load, LTV auto-load, Churn on-demand | Todos on-demand | Los 3 primeros son datos que el staff consulta regularmente. Churn es decisión que requiere intención explícita |
| 4 | Brain icon para sidebar | Heart (ya usado por Engagement), Activity, BarChart3 | Brain es semánticamente correcto para "inteligencia" y no duplica ningún icono existente |
| 5 | "Inteligencia" como label de sidebar | "Inteligencia de Socios", "Members AI", "Analytics" | Consiso, consistente con "Engagement", "Documentos" — una sola palabra |
| 6 | Roles [ADMIN, JUNTA] para la ruta | Solo [ADMIN] | Junta necesita acceso a inteligencia de membresía para decisiones estratégicas |
| 7 | Gauge radial con PieChart custom | Gauge SVG manual o librería externa | Recharts nativo, consistente con el stack, suficiente para el efecto visual |
| 8 | Radar chart con 2 series (actual + anterior) | Solo 1 serie | La comparación temporal es el insight más valioso — el delta importa más que el valor absoluto |
| 9 | Treemap con custom SVG cell | Treemap default de Recharts | Default no permite tipografía ni layout control. Custom cell da control total del SVG |
| 10 | Fan chart con 5 stacked Areas | Error bars | Stacked areas dan la sensación visual de "abanico" que comunica incertidumbre intuitivamente |
| 11 | Migration matrix como heatmap desktop + list mobile | Solo heatmap responsive | Heatmap en mobile es ilegible. List con badges es más usable |
| 12 | Persona profiles como expandibles en línea | Página dedicada | El usuario necesita comparar personas sin perder contexto. Expandibles mantienen el flujo |
| 13 | SEGMENT_COLORS como Record<string, string> con hex | Usar directamente CHART_PALETTE | Los segmentos tienen identidad semántica propia (deportivos=teal) que no siempre mapea a la paleta genérica. Pero los hex coinciden para Recharts |
| 14 | ExportButton con solo onPrint() en 14c | Agregar data prop para narrative export | Los componentes de 14c no tienen narrative engine propio. Future: cuando haya member_narrative_generate, agregar data |
| 15 | Historical saves como tabla + mobile cards | Timeline visual | Los saves no son un flujo temporal — son registros individuales. Tabla es más informativa |
| 16 | Cost of Inaction banner como primer elemento en ChurnPrevention | Al final como insight | Impacto emocional: el usuario ve el costo de NO actuar ANTES de ver las opciones. Motiva a continuar |
| 17 | Custom ScatterTooltip y FanTooltip | Tooltip genérico | Los datos tienen formato específico (monedas, percentiles, tier) que un tooltip genérico no muestra bien |
| 18 | Intervention playbook expandible | Tabla de intervenciones | La description completa es demasiado larga para una tabla. Expandibles permiten progressive disclosure |
