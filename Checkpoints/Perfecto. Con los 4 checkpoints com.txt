## PASO 4 — PROPUESTA PROACTIVA

### Arquitectura de Member 360

**Concepto clave:** Member 360 NO es un dashboard más. Es un **Member Data Service** — una capa que unifica datos de TODOS los dominios para un socio individual, y que CUALQUIER otro componente/advisor puede consumir.

```
                    ┌──────────────────────────────────┐
                    │     MEMBER 360 DATA SERVICE       │
                    │                                   │
                    │  useMember360(memberId)           │
                    │  ├── identity (tier, role, family)│
                    │  ├── engagement (score, level)    │
                    │  ├── financial (LTV, balance)     │
                    │  ├── lifecycle (stage, journey)   │
                    │  ├── churn (risk, factors)        │
                    │  ├── health (composite score)     │
                    │  ├── activities (cross-domain)    │
                    │  ├── social (connections)         │
                    │  ├── satisfaction (NPS, sentiment)│
                    │  └── communications (channels)    │
                    └──────────────┬───────────────────┘
                                   │
              ┌────────────────────┼────────────────────┐
              │                    │                    │
    ┌─────────▼──────┐  ┌─────────▼──────┐  ┌─────────▼──────┐
    │ Family Advisor │  │ Financial Adv  │  │ Global Advisor │
    │ consume 360    │  │ consume 360    │  │ consume 360    │
    │ para rules     │  │ para LTV       │  │ para systemic  │
    └────────────────┘  └────────────────┘  └────────────────┘
```

**Por qué es diferente de `family_360_insight`:**
- `family_360_insight` = vista agregada por FAMILIA
- Member 360 = vista por SOCIO INDIVIDUAL (titular, conyuge, hijo, dependiente)
- Un socio puede tener engagement alto aunque su familia tenga engagement bajo
- Churn individual es diferente a churn familiar
- LTV individual permite targeted retention
