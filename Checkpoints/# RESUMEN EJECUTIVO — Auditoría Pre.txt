## PARTE 1: ESTADO DE SALUD DEL PROYECTO

### Veredicto general: **SOLIDO con deuda técnica controlada**

El proyecto tiene una arquitectura madura, un design system consistente, y un patrón AI bien establecido. La deuda técnica es proporcional a la velocidad de desarrollo (22 fases). Los problemas son específicos y tienen solución clara — no hay fallas sistémicas.

### Lo que funciona excepcionalmente bien

| Aspecto | Evidencia |
|---------|-----------|
| **Mock system** | Contracts → Factories → Registry pattern es elegante. Para migrar a backend real: eliminar key, 0 cambios en componentes |
| **AI Intelligence Pattern** | Consolidado en Fase 17/18. Config array + enabled state + on-demand queries + ScoreGauge shared. Replicable a cualquier módulo |
| **HITL Flow** | 3 patrones claros: approval→pending_approval→showToast info, conditional escalation (>4 guests→HITL), dual approval model |
| **Backend alignment (AI types)** | Los 14 AI types de finance están 100% alineados con los modelos Pydantic del backend. Zero transformation needed |
| **Token discipline** | ~95% del frontend usa tokens del Silver Tide design system. Las violaciones son concentradas y fixeables |
| **Shared components** | Button, Badge, Card, EmptyState, DetailTabs, PageContainer, ScoreGauge — todos usados consistentemente |

## PARTE 2: HALLAZGOS CRÍTICOS (requieren fix antes de Fase 19)

### C1 — `FinancialDashboard.tsx`: Bug en sub-tabs de Herramientas

```
SEVERIDAD: CRÍTICA (feature rota)
ARCHIVO: frontend/src/features/finance/FinancialDashboard.tsx
```

**Problema:** Cuando el usuario clickea "Presupuesto" o "Reportes" dentro de la tab "Herramientas", `setActiveTab(tab.id)` cambia `activeTab` a `"budget"` o `"reportes"`. Pero el render dice `{activeTab === "tools" && (...)}` — esto es FALSE, así que **ningún sub-componente se renderiza**. El usuario ve pantalla vacía.

**Fix quirúrgico:**

Encontrá estas líneas en el onClick de los sub-tab buttons (~línea 121):

```tsx
onClick={() => {
  setToolTab(tab.id);
  setActiveTab(tab.id);  // ← ESTA LÍNEA ROMPE EL RENDER
}}
```

Reemplazá por:

```tsx
onClick={() => {
  setToolTab(tab.id);
  // NO cambiar activeTab — debe permanecer en "tools"
}}
```

### C3 — `FamilyDetail.tsx`: `formatUSD` en vez de `formatCurrency` (₡)

```
SEVERIDAD: CRÍTICA (wrong currency — Costa Rica usa colones)
ARCHIVO: frontend/src/features/families/FamilyDetail.tsx
```

**Problema:** Todo el componente usa `formatUSD` para montos. El backend usa ₡ (colones). Los socios ven `$150,000` en vez de `₡150,000`.

**Fix:** Encontrá el import:

```tsx
import { cn, formatUSD, getAgeGroup, calculateAge } from "@/shared/lib/utils";
```

Reemplazá por:

```tsx
import { cn, formatCurrency, getAgeGroup, calculateAge } from "@/shared/lib/utils";
```

Luego reemplazá TODAS las ocurrencias de `formatUSD(` por `formatCurrency(` en el archivo (~10-12 ocurrencias).

**Verificación adicional:** Confirmá que `formatCurrency` en `shared/lib/utils.ts` usa ₡ (colones). Si no, actualizalo:

```typescript
export function formatCurrency(amount: number): string {
  return new Intl.NumberFormat('es-CR', {
    style: 'currency',
    currency: 'CRC',
    minimumFractionDigits: 0,
    maximumFractionDigits: 0,
  }).format(amount);
}
```

### C4 — `mock-registry.ts`: Special case de `generate_ai_analysis` intercepta el mock correcto

```
SEVERIDAD: MEDIA (resuelta por diseño — el panel NO pasa scope)
ARCHIVO: frontend/src/shared/mocks/mock-registry.ts
```

**Problema:** `getMockResponse()` tiene un special case que intercepta `generate_ai_analysis` con `scope === "financial"` y devuelve `createFinancialAIReport()` (de executive_dashboard) en vez de `createMockGenerateAiAnalysis()` (de finance).

**Resolución:** El `FinanceIntelligencePanel` que crearemos NO pasa `scope` como parámetro. Solo pasa `{ period }`. Sin `scope`, el special case no intercepta, y el flujo cae al registry → factory correcta.

**No requiere fix en el registry.** Solo asegurar que el nuevo panel no envíe `scope`.

## PARTE 3: HALLAZGOS DE ALTA SEVERIDAD (fix en Fase 19)

### A1 — Agent name discrepancy entre `approvals/types.ts` y `ApprovalQueue.tsx`

```
SEVERIDAD: ALTA
```

Hay dos `AGENT_LABELS` definidos con nombres diferentes:

| Source | `communication` key | Agent names |
|--------|-------------------|-------------|
| `approvals/types.ts` | `communication_agent` | Nombres largos: `event_orchestrator`, `family_profile`, etc. |
| `ApprovalQueue.tsx` | `communication` | Nombres cortos: `finance`, `events`, etc. |

**El real** (verificado contra backend agents):
- `finance.py` → `agent_name = "finance"` ✅
- `family_profile.py` → `agent_name = "family_profile"` (NO `"families"`)
- `guest_management_agent.py` → `agent_name = "guest_management"`
- `proactive_recommendation_agent.py` → `agent_name = "proactive_recommendation"`
- `event_orchestrator.py` → `agent_name = ?` (no leído, pero el nombre del archivo sugiere `"event_orchestrator"`)

**Fix:** Consolidar `AGENT_LABELS` en `approvals/types.ts` como source of truth. ApprovalQueue importa de ahí. Agregar todos los agents que faltan.

### A2 — `PrivateEventPlanner.tsx`: Sin HITL flow para create

```
SEVERIDAD: ALTA
```

`plan_private_event` (create) devuelve `pending_approval`. El componente muestra `showToast({ type: "success" })` en vez de `showToast({ type: "info", message: "Pendiente de aprobación" })`.

**Fix:** Implementar el patrón HITL consolidado (mismo que EventForm y FamilyForm):

```typescript
onSuccess: (data) => {
  if (data?.status === "pending_approval") {
    showToast({ type: "info", message: "Solicitud enviada — pendiente de aprobación" });
    setShowCreate(false);
    eventsQ.refetch();
    return;
  }
  showToast({ type: "success", message: data.message ?? "Evento registrado" });
  // ...
}
```
