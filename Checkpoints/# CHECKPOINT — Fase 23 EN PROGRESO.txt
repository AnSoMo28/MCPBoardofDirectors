## 4. PATRONES ESTABLECIDOS / ACTUALIZADOS

### Patrón NUEVO: Adaptive Thresholds Engine (F23)

**Concepto:** Thresholds que se adaptan a contexto (temporada CR, fitness level) en vez de magic numbers hardcoded.

**Niveles:**
```
Nivel 0: computeThreshold(config, fitnessLevel?) → AdaptiveThresholdResult
Nivel 1: WELLNESS_THRESHOLDS.* (factory functions pre-built)
```

**Fórmula:** `effective = (base + seasonalDelta) × fitnessMultiplier`

**Ejemplo:**
```typescript
const threshold = WELLNESS_THRESHOLDS.healthScoreCritical("beginner");
// base=40, seasonal=0 (transition), fitness×0.85 (beginner)
// effective = (40 + 0) × 0.85 = 34
```

**Cuándo se aplica:** Cualquier regla Advisor que compare un valor contra un threshold
**Fases futuras donde se replica:** F25 (migrar Financial/Event/Global Advisors)
**Archivos donde ya está implementado:** `shared/lib/adaptiveThresholds.ts`, `features/wellness/hooks/useWellnessAdvisor.ts`

### Patrón NUEVO: Wellness Personas Engine (F23)

**Concepto:** Clasificación determinística de socios en 8 perfiles de bienestar basada en activity patterns.

**Perfiles:** athlete, zen_seeker, social_butterfly, weekend_warrior, recoverer, explorer, dormant, newcomer

**Cuándo se aplica:** Regla 15 del Wellness Advisor (fusion layer)
**Archivos donde ya está implementado:** `features/wellness/lib/wellnessPersonas.ts`, `features/wellness/hooks/useWellnessAdvisor.ts`

### Patrón NUEVO: Family Selector para Domain Dashboards (F23)

**Concepto:** Para dominios donde ADMIN no tiene `family_id`, componente selector reutilizable con búsqueda y lista de familias.

**Cuándo se aplica:** Cuando un dashboard es por-familia pero el ADMIN no tiene familia asignada
**Archivos donde ya está implementado:** `features/wellness/WellnessDashboard.tsx` (inline, refactorizar a shared en F25)

### Reglas del Wellness Advisor:

**Macro (1-5) — Score & Profile Intelligence:**
1. `wellness_health_critical` — composite < adaptive threshold (HIGH)
2. `dimension_dragging` — una dimensión < 25, composite > 50 (MEDIUM)
3. `fitness_mismatch_underutilized/overexertion` — profile vs actual pattern (MEDIUM)
4. `trend_declining` — trend dimension < 35, prevReport exists (HIGH)
5. `health_conditions_no_adaptation` — health_conditions sin spa/yoga/meditation (HIGH)

**Micro (6-11) — Activity & Engagement Intelligence:**
6. `activity_drought` — streak=0 + total<2 (HIGH, with action)
7. `monotony_risk` — top activity > 75% del total (MEDIUM)
8. `social_isolation` — 0 actividades sociales en N total (MEDIUM, with action)
9. `goal_stagnation` — high-priority recs ignoradas + low activity (MEDIUM)
10. `streak_broken` — prev streak ≥ 7, current streak = 0 (HIGH, with action)
11. `overtraining_signal` — total > adaptive threshold por fitness level (MEDIUM)

**Fusion (12-15) — Cross-Domain & Persona Intelligence:**
12. `compound_churn_risk` — composite < compoundRisk threshold + trend < 0 (HIGH)
13. `premium_candidate` — composite > 75 + intermediate/advanced + streak ≥ 7 (MEDIUM)
14. `recommendations_gap` — ≥3 recs + total activity 2-5 (MEDIUM)
15. `persona_*` — WellnessPersona classification (HIGH if dormant, LOW otherwise)
