## 3. PATRONES ESTABLECIDOS

### Patrón NUEVO: Export Intelligence System

**Cuándo se usa:** Cuando cualquier módulo necesita exportar datos al usuario.

```
1. ExportButton (shared) — dropdown con opciones contextuales
   ├── "Imprimir / PDF" → onPrint callback (window.print() o PrintView)
   ├── "Copiar texto" → formatNarrativeAsText() → clipboard
   ├── "CSV" → formatNarrativeAsCSV() → downloadBlob
   ├── "Excel" → CSV blob with .xlsx mime → downloadBlob
   └── "Documento de Decisión" → onDecisionDocument callback (overlay)
2. Las opciones se filtran por props proporcionadas:
   - data prop → habilita text/CSV/Excel
   - onPrint prop → habilita Imprimir/PDF
   - onDecisionDocument prop → habilita Documento de Decisión
3. window.print() directo para módulos sin narrative data
4. PrintView wrapper para módulos con narrative data estructurada
5. DecisionDocument para combinación de múltiples MCP tools
```

**Implementación:**
- `shared/services/exportService.ts` — utilidades puras (filename, download, text, CSV)
- `shared/components/export/ExportButton.tsx` — UI dropdown
- `shared/components/export/PrintView.tsx` — narrative print (usa wrapper de dashboard)
- `shared/components/export/DecisionDocument.tsx` — documento combinado 3 MCP tools

**Se replica en:** Cualquier módulo que tenga datos exportables (wellness, engagement, communications, guests)

### Patrón NUEVO: Narrative Engine (AI-Generated Executive Briefing)

**Cuándo se usa:** Cuando se necesita convertir datos crudos en inteligencia ejecutiva accionable.

```
1. Control bar con 3 selectores: Período, Audiencia, Nivel de detalle
```

**Ejemplo:** NarrativeEngine.tsx

### Patrón NUEVO: Multi-Query Decision Document

**Cuándo se usa:** Cuando se necesita combinar datos de múltiples MCP tools en un solo documento.

```
1. Overlay full-screen (position: fixed, z-100)
2. Toolbar con status "X/3 módulos cargados"
3. 3 queries on-demand con enabled: isOpen (Rule #19)
4. Loading skeletons mientras fetcha
5. Fallback graceful si un tool no tiene data ("No disponible")
6. Secciones numeradas: 1. Situación → 2. Escenarios → 3. Stress → 4. Insights → 5. Recs → 6. Risks
7. Print con window.print() nativo
8. .no-print en toolbar (se oculta al imprimir)
```

**Ejemplo:** DecisionDocument.tsx
**Se replica en:** Futuros documentos combinados (Operational Report, Member Intelligence Report)

### Patrón CONFIRMADO: Reutilización de Componentes de Impresión

```
PrintView existente (dashboard) es genérico:
  - Props: children, title, subtitle, printDate, hideTrigger
  - Renderiza: A4 page con branding del club, header, footer
  - Estilos: inline <style> con @media print completo

Componentes específicos (narrative, etc.) lo envuelven:
  - <PrintViewWrapper title="..." subtitle="...">
      {/* contenido específico renderizado con inline styles print-safe */}
    </PrintViewWrapper>

NO crear @media print separados — conflicto de especificidad.
NO crear archivos .css para print — usar inline styles + wrapper existente.
Utility classes (.page-break-avoid, .no-print) van en globals.css.
```

## 4. DECISIONES DE DISEÑO

| # | Decisión | Alternativa descartada | Razón |
|---|---------|----------------------|-------|
| 1 | Fase 14b como "Export Intelligence" con Narrative Engine integrado | Export genérico (PDF/CSV) sin AI | Transforma un PDF genérico en herramienta de toma de decisiones para la junta |
| 2 | 4 etapas progresivas (14b→14c→14d→15ext) | Todo junto en 14b | Entregable incremental, cada fase tiene valor independiente |
| 3 | Narrative Engine como sub-tab #7 (último) en FinancialIntelligence | Primer tab | Respeta flujo lógico: explorar datos → simular → analizar → narrar como síntesis |
| 4 | Label "Motor de Narrativa" (del usuario) | "Narrativa AI" (propuesto) | Más descriptivo y profesional |
| 5 | Mock-registry rewrite completo en B0 | Fix quirúrgico solo de imports faltantes | 8 bugs encontrados — fix completo evita efecto cascada |
| 6 | `getMockResponse` pasa `params` a factories | Mantener `factory()` sin params | Todas las factories con params recibían undefined — bug silencioso |
| 7 | ExportButton dropdown reutilizable | Botones individuales por módulo | Un componente para todos los módulos, opciones contextuales por props |
| 8 | `window.print()` directo para módulos sin narrative data | PrintView wrapper para todos | FinanceOverview, ReportGenerator, MemberProfitability no necesitan PrintView — el navegador maneja el PDF |
| 9 | PrintView de export usa wrapper existente de dashboard | PrintView independiente con sus propios @media print | Evita duplicación y conflictos de especificidad CSS |
| 10 | `print.css` borrado, utility classes en `globals.css` | Archivo externo separado | Conflicto con inline `<style>` de PrintView existente |
| 11 | ExportButton en ReportGenerator alongside "Generar Reporte" | Reemplazar "Generar Reporte" | "Generar" es mutation, "Exportar" es output — acciones complementarias |
| 12 | ExportButton en MemberProfitability en chart header | Toolbar separada | Un solo botón no justifica toolbar completa |
| 13 | DecisionDocument hace 3 queries simultáneas al abrir | Queries secuenciales | Todas son mocked con staleTime, paralelo es más rápido |
| 14 | FinanceOverview: ExportButton con window.print() directo | Wrap en PrintView con hideTrigger | Over-engineering — no tiene narrative data que renderizar |
| 15 | CommunicationCenter NO recibe ExportButton | Agregar ExportButton placeholder | No tiene botón existente ni datos exportables claros |
