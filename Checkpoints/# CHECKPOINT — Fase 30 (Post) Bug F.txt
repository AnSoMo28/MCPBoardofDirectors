## 3. PATRONES ESTABLECIDOS

### Pattern: Self-Reference Filtering (Mock Data)

Cuando un mock devuelve datos de "relaciones" (social graph, connections, etc.) y el componente recibe un `familyId` como parámetro, SIEMPRE filtrar self-reference:

```typescript
// En factory
export function createMockSomething(params?: Record<string, unknown>): ... {
  const viewingId = (params?.familyId as string) ?? "fam-001";
  // Return connections — may include self if mock is static
}

// En componente (initializeNodes)
const filteredConnections = connections.filter(
  (c) => c.connectedFamilyId !== familyId,
);
```

**Se aplica en:** cualquier mock de "relaciones" donde el dataset es estático pero se ve desde distintas perspectivas.

### Pattern: Dynamic Mock Lookup by ID

Cuando un mock devuelve datos de un entity específico pero el dataset es estático:

```typescript
const FAMILY_PROFILES: Record<string, { name: string; tier: string; ... }> = {
  "fam-001": { name: "...", tier: "oro", ... },
  "fam-002": { name: "...", tier: "platino", ... },
  // ...
};

export function createMockDetail(params?: Record<string, unknown>) {
  const id = (params?.familyId as string) ?? "fam-001";
  const profile = FAMILY_PROFILES[id] ?? FAMILY_PROFILES["fam-001"];
  // Build response from profile
}
```

**Se aplica en:** `createMockFamilyDetail`, y cualquier detail view que deba mostrar datos distintos según el ID.

### Pattern: Canvas Token Resolution

Para Canvas 2D que necesita hex (no puede usar CSS vars directamente):

```typescript
function resolveColors(): ResolvedColors {
  const get = (name: string) =>
    getComputedStyle(document.documentElement).getPropertyValue(name).trim();
  return {
    gold400: get("--color-gold-400"),
    emerald400: get("--color-emerald-400"),
    // ... todos los tokens necesarios
  };
}

function hexToRgba(hex: string, alpha: number): string {
  const h = hex.replace("#", "");
  const r = parseInt(h.slice(0, 2), 16);
  const g = parseInt(h.slice(2, 4), 16);
  const b = parseInt(h.slice(4, 6), 16);
  return `rgba(${r}, ${g}, ${b}, ${alpha})`;
}
```

**Se aplica en:** `SocialGraph` canvas renderer. Rule #1 compliant.

## 4. DECISIONES DE DISEÑO

| Decisión | Alternativa descartada | Razón |
|----------|----------------------|-------|
| `getMockResponse` interceptación condicionada por server | Eliminar la interceptación | Executive dashboard necesita su propio routing por scope — solo se restringe a ese server |
| `?? 0` defensivo en FinanceAnalytics | Corregir el mock | Más resiliente — protege contra backend parcial Y mocks incompletos |
| `data?.families` directo (FamilyList) | Agregar wrapper al mock | El mock sigue el contract `FamilyListResponse` — el componente estaba mal |
| Self-reference filter en SocialGraph | Hacer mock dinámico por familyId | El graph mock es compartido — el filtro es más simple y no requiere duplicar data |
| Canvas dark fills + colored borders en vez de solid color fills | Tintes sutiles con mezcla | User feedback: "los colores sólidos en los círculos se ven feos" |
| Restaurar physics original de SocialGraph | Layout determinístico radial | Physics daba animación suave de convergencia que el usuario prefería. Determinístico se veía "robotizado" |
| Pin center node post-simulation | Force simulation con anchor | Más simple, más confiable — la física no puede garantizar que el centro no se desplace |
| `FAMILY_PROFILES` lookup estático | Mock que recibe params y genera data aleatoria | Datos consistentes y verosímiles para cada familia — mejor para debugging y demo |
