## 4. PATRONES ESTABLECIDOS / ACTUALIZADOS

### Patrón NUEVO: Analytics Event Tracking (F24)

**Concepto:** Lightweight client-side event tracking para AI tools. localStorage-based, preparado para backend endpoint.

**API:**
```typescript
trackEvent("board_brief", "pdf_exported")
trackEvent("advisor_narrative", "expanded", "revenue_concentration_001")
getAnalyticsSummary() // → { "board_brief:opened": 5, ... }
```

**Cuándo se aplica:** Cualquier componente AI que necesitemos medir engagement.
**Fases futuras donde se replica:** F26+ (backend endpoint), F24+ (otros AI tools)
**Archivos donde ya está implementado:** `shared/lib/analytics.ts`, `shared/components/ai/AIBoardBriefViewer.tsx`

### Patrón NUEVO: Dynamic Simulation Context (F24)

**Concepto:** Proposed changes para simulation se generan automáticamente basados en los insights activos del Advisor, en vez de hardcodearse.

**Implementación:** `generateProposedChanges()` en `GlobalAdvisorBanner.tsx` — 5 keyword clusters: revenue/margin, churn/retention, events, wellness, fallback genérico.

**Cuándo se aplica:** Cuando un Advisor Banner tiene Simulation Panel
**Archivos:** `features/dashboard/components/GlobalAdvisorBanner.tsx`

### Patrón NUEVO: Advisor Chat Action Bridge (F24)

**Concepto:** Advisor Chat suggested actions se ejecutan via el mismo action bridge que las acciones de los Banners. Routing por `server + tool` con fallback a `callMCPTool` genérico.

**Cuándo se aplica:** Cuando el Advisor sugiere una acción en modo conversacional
**Archivos:** `features/dashboard/ExecutiveDashboard.tsx`

### Patrón NUEVO: Shared Advisor UI Config (F25)

**Concepto:** IMPACT_CONFIG y otros configs compartidos entre Advisor banners centralizados en `shared/lib/ui/advisorConfig.ts`.

**Cuándo se aplica:** Todos los Advisor banners
**Archivos:** `shared/lib/ui/advisorConfig.ts`, `GlobalAdvisorBanner.tsx`, `WellnessAdvisorBanner.tsx`

## 6. DECISIONES DE DISEÑO

| # | Decisión | Alternativa descartada | Razón | Impacto |
|---|---------|----------------------|-------|---------|
| 1 | Talking Points visibles en UI además de PDF | Solo en PDF | ADMIN lee briefs en browser, no solo exporta | UX improvement |
| 2 | `generateProposedChanges()` basado en keywords de insights | proposedChanges como parte de insight data | No requiere cambiar Advisor hooks. Más flexible. | Simulation context-aware sin cambios en hook |
| 3 | IMPACT_CONFIG labels genéricos (Alto/Medio/Bajo) | Labels específicos por dominio (Crítico/Atención/Info) | Consistencia cross-banner es más importante que labels específicos | Wellness banner pierde labels específicos |
| 4 | `SEASON_CONFIG` inline en adaptiveThresholds | Mover a archivo shared separado | Solo se usa en adaptiveThresholds. No justifica archivo propio. | Elimina dependency inversion |
| 5 | Swimming como NON-social | Swimming como social | En CR, natación es actividad individual (lap swimming). Consistent con `ACTIVITY_TYPE_CONFIG.swimming.social=false` | Score engine y Advisor rule 8 ahora alineados |
| 6 | `compactCurrency` como función exportada | No centralizar (dejar duplicados) | 3+ definiciones locales causan drift | Importar de shared/lib/utils en F25+ |
| 7 | Analytics localStorage-based | Backend endpoint inmediato | Más rápido de implementar. Preparado para backend (F26+) | Tracking existe hoy, backend viene después |
| 8 | `handleAdvisorChatAction` busca matching insight por server+tool | No vincular chat actions con reaction system | Reacciones del Advisor Chat se ven en el banner también | Feedback loop completo |
| 9 | Bloque 3 original (Conversation History) fue eliminado del plan | Implementar de nuevo | Ya existía desde F22a — verificación descubrió que el feature no estaba dormido | Ahorro de tokens/tiempo |
| 10 | Advisor Chat button raw → no se hizo swap aquí | Button swap en toggle/close/send | Toggle es FAB flotante (excepción aceptable), close ya tiene patrón en otros widgets | Pendiente para F25 polish futuro |
| 11 | Usuario RECHAZÓ instrucciones ambiguas ("agregar al existente") | Seguir con instrucciones vagas | Causó duplicación de atributos. Nueva regla: siempre reemplazar bloque completo | **Regla de formato establecida** (ver sección 0) |
| 12 | REWRITE de AISimulationPanel fue entregado como archivo completo | Bloque por bloque | Usuario indicó: rewrite = rewrite completo, no perder tokens bloque por bloque | **Regla de formato establecida** |
| 13 | `font-body` eliminado de todo el proyecto | Definir `--font-body` como token | Silver Tide no define body font como CSS variable. `font-ui` (DM Sans) es el correcto para body text | 11 instancias corregidas |
| 14 | Wellness Advisor Banner IMPACT_CONFIG labels cambiados | Mantener labels específicos | Usuario no objetó el cambio a genéricos | Consistencia cross-banner |
