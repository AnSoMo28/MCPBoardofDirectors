## 3. PATRONES ESTABLECIDOS

### Patrón: MCP Data Access (establecido en sesiones anteriores, reafirmado aquí)

```typescript
// Pattern: MCP response wrapper access
const { data, isLoading, isError, error } = useMCPQuery<ResponseType>(
  "server", "tool", params, options
);

// SIEMPRE acceder a .data del wrapper
const payload = data?.data;
if (!payload?.expectedField) {
  return <EmptyState ... />;
}
const { field1, field2 } = payload;
```

**Regla:** TODOS los `useMCPQuery` deben acceder a `data?.data` (no `data` directo) y tener guard contra undefined.

### Patrón: Component Migration (nuevo en esta sesión)

```typescript
// ANTES (inline styles — 15-20 líneas por elemento)
<div className="p-5 rounded-[var(--radius-lg)] bg-[var(--color-surface-2)] border border-white/[0.08] shadow-[var(--shadow-card)]">
  contenido
</div>

// DESPUÉS (1-2 líneas usando componentes del design system)
<Card className="p-5" tone="gold" hover={false}>
  contenido
</Card>
```

**Mapping de tones por contexto:**
- `gold` → Premium, VIP, gala, reconocimiento, membresía
- `teal` → Datos financieros, información, bienestar
- `emerald` → Éxito, crecimiento, positivo
- `silver` → Neutro, contacto, formal
- `terracotta` → Tierra, charts, actividades
- `rose` → Errores, crítico, cancelaciones

### Patrón: Button Usage (nuevo en esta sesión)

```typescript
// Primary actions — gold sweep
<Button variant="primary" icon={<Plus />} onClick={...}>Crear</Button>

// Secondary actions — silver sweep
<Button variant="secondary" onClick={...}>Hoy</Button>

// Ghost/navigate — subtle silver sweep
<Button variant="ghost" icon={<ArrowLeft />} onClick={...}>Volver</Button>

// Danger — rose sweep
<Button variant="danger" icon={<AlertTriangle />} onClick={...}>Eliminar</Button>

// Sage — green sweep (eco, wellness)
<Button variant="sage" onClick={...}>Aprobar</Button>
```

### Patrón: Badge Usage (nuevo en esta sesión)

```typescript
// Status badges
<Badge variant="success" dot>Publicado</Badge>
<Badge variant="error" dot>Cancelado</Badge>
<Badge variant="neutral">Borrador</Badge>

// Tier badges
```

## 4. DECISIONES DE DISEÑO

| # | Decisión | Alternativa descartada | Razón |
|---|---------|----------------------|-------|
| D1 | `lunar-btn` (diagonal sweep) en vez de `aurora-btn` (horizontal sweep) | Mantener aurora-btn como único | Sweep diagonal es más elegante y distintivo. Aurora se mantiene como fallback. |
| D2 | `Card.tsx` como componente principal de superficies (no deprecado) | Crear `SurfaceCard` nuevo | Card.tsx ya usa `.glass-card` + `data-tone` + `glow-card` correctamente |
| D3 | `FrostedGlassCard` para hero/featured, `Card` para datos | Usar solo uno | Propósitos diferentes: FrostedGlassCard es artístico (canvas), Card es funcional (CSS glass) |
| D4 | `inputClass` unificado a glass (rgba + backdrop-blur) | Mantener sólido y glass separados | Consistencia con `Input.tsx` y `.glass-input` del global.css |
| D5 | `find-and-replace` global para 3 patrones de glass | Archivo por archivo | Patrones exactos y context-independientes |
| D6 | QuickAddPanel crea eventos como `draft` directamente | Siempre redirigir a EventForm | UX: flujo rápido para eventos simples, "Detalles avanzados" para el wizard completo |
| D7 | QuickAddPanel lee eventos del día para conflict detection | No mostrar conflictos | Prevención de overbooking y scheduling conflicts |
| D8 | Pre-fill via URL params (no state management global) | Context/Redux/zustand | Simple, no requiere dependencias extra, funciona con back/forward navigation |
| D9 | `hover:bg-white/[0.04]` → `hover:bg-[var(--color-surface-3)]` globalmente | Mantener glass hover | El hover glass hace texto ilegible |
| D10 | Badge de FrostedGlassCard usa `.frost-badge` CSS class | Mantener inline styles | Centralización de estilos en global.css |

## 8. ACTUALIZACIONES PARA CLAUDE_CONTEXT_MINI.md

### Sección: Design System Architecture — AGREGAR

```markdown
## Design System Architecture (Silver Tide)

### Surface Hierarchy
- **FrostedGlassCard** (canvas): Hero cards, featured content, artístico. Renderizado canvas con frost patterns.
- **Card** (CSS `.glass-card`): Datos, formularios, dashboards. Usa `data-tone` para tintes contextuales.
- **stat-surface** (CSS): Hover states, filas clickeables, items interactivos.
- Card.tsx NO está deprecado — es el componente principal de superficies.

### Button System
- **Button.tsx** usa `.lunar-btn` (sweep diagonal elegante)
- Variantes: primary(gold), sage(emerald), secondary(silver), ghost(silver), danger(rose)
- Aurorabtn se mantiene como fallback en global.css

### Glass Transparency Rules (CRÍTICO)
- NUNCA usar `bg-white/[0.04]` como fondo principal
- NUNCA usar `hover:bg-white/[0.04]` o `hover:bg-white/[0.06]` como hover
- SIEMPRE usar: `bg-[var(--color-surface-N)]` para fondos, `hover:bg-[var(--color-surface-3)]` para hover
- Exception: `bg-[rgba(255,255,255,0.04)]` con backdrop-blur es OK para inputs glass

### Component Imports (OBLIGATORIO)
- Cards de datos → `import { Card } from "@/shared/components/ui/Card"`
- Botones → `import { Button } from "@/shared/components/ui/Button"`
- Badges/tags → `import { Badge } from "@/shared/components/ui/Badge"`
- Inputs → `import { Input } from "@/shared/components/ui/Input"` o `FormField` + `inputClass`
- NO re-inventar estilos inline

### Tone Mapping
- gold → Premium, VIP, membresía, gala
- teal → Financial, datos, wellness
- emerald → Éxito, positivo, crecimiento
- silver → Neutro, contacto, formal
- terracotta → Charts, actividades, tierra
- rose → Errores, crítico, cancelaciones
```
