2. Design System — Silver Tide

Regla de oro
NUNCA colores hardcoded. Todos los colores deben usar tokens del @theme en globals.css. Los maps de config (*_CONFIG) usan siempre var(--color-xxx).


Token map

Categoría	Tokens disponibles
Superficies	--color-abyss, --color-surface-0/1/2/3
Texto	--color-silver-100 a --color-silver-600
Gold (marca)	--color-gold-50 a --color-gold-700
Teal (info/datos)	--color-teal-100 a --color-teal-600
Emerald (éxito)	--color-emerald-100/300/400/500
Amber (warning)	--color-amber-300/400/500
Rose (error)	--color-rose-100/300/400/500
Terracotta (warm)	--color-terracotta-300/400/500
Sage (verde elegante)	--color-sage-100 a --color-sage-600
Shadows	--shadow-soft/card/elevated/gold/teal/rose
Radius	--radius-sm/md/lg/xl/2xl
Glass tokens	--glass-bg/border y variantes
Chart palette	--chart-primary/secondary/tertiary/warm/neutral/highlight
Semantic bg	--color-emerald-bg/amber-bg/rose-bg/teal-bg/critical-bg

Patrón de colores en config maps
tsx
tsx
// Correcto
{ color: "var(--color-gold-400)", bgColor: "color-mix(in srgb, var(--color-gold-400) 12%, transparent)" }

// INCORRECTO — nunca
{ color: "#C9A96E", bgColor: "rgba(201, 169, 110, 0.12)" }

3 niveles de superficie

Nivel	Implementación	Uso
Hero	FrostedGlassCard (canvas)	Portadas visuales, instalaciones, perfiles destacados. Altura fija 252px, frost único por tarjeta.
Data Card	<Card> → .glass-card CSS	Items individuales en listas. Glass treatment con rain effect.
Data Container	bg-[var(--color-surface-2)] + border-white/[0.06] + shadow-[var(--shadow-card)]	Wrappers: tablas, grids, secciones. Sólido, sin backdrop-filter.

Problema conocido: backdrop-filter + WebGL
backdrop-filter en glass-card y stat-surface puede interferir con el WebGL background, causando transparencias no deseadas. Solución: usar superficies sólidas (bg-surface-2) para containers data-dense. El glass CSS funciona bien para cards individuales.

4. Decisiones arquitectónicas clave

Decisión	Detalle
DevBypass	App.tsx tiene devBypass() activo. Para quitarlo, eliminar el useEffect que llama devBypass().
Auth backend	Puerto 8001. Vite proxy redirige /api/*. Login devuelve { tokens: { access_token, refresh_token }, user: {...} }. Roles lowercase del backend → uppercase en frontend.
PermissionGate	Se usa con roles en el router. ADMIN tiene acceso total vía hasPermission().
FrostedGlassCard	Solo para hero/visual cards (canvas frost, 252px fijo). No para data-dense.
glass-card CSS	Para data cards individuales. Funciona bien contra superficies sólidas.
bg-surface-2 sólido	Para containers (tablas, grids). Sin backdrop-filter.
Nombres de ruta	/admin/* para staff/admin/junta. /mi-club/* para socios. /operaciones/* para staff. /junta/* para junta.
LoginPage	Excluida del trabajo. No se migra.
