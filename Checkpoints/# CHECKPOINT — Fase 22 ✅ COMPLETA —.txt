## 3. PATRONES ESTABLECIDOS

### Patrón: Advisor Reaction System (F22b)

**Concepto:** Loop cerrado de feedback para las acciones del Advisor. Cuando el usuario ejecuta una acción (AUTO, HITL, o SEMI), el sistema genera un "reaction insight" con impacto estimado, confianza, y siguiente paso sugerido. Se renderiza inline en el banner.

**Niveles:**
```
1. Acción del Advisor → onExecute(insightId) o handleModalConfirm()
2. Mutation exitosa → generateReactionInsight(action, insightId)
3. Reaction se agrega al array de reactions (state del shell)
4. Shell pasa reactions={reactions} al Banner
5. Banner renderiza AdvisorReactionCard por cada reaction (más reciente primero)
```

**Ejemplo de código — Shell (ExecutiveDashboard/FinancialDashboard/EventCalendar):**
```typescript
import { generateReactionInsight } from "@/shared/lib/reactionTemplate";
import type { AdvisorReactionInsight } from "@/features/dashboard/types";

const [reactions, setReactions] = useState<AdvisorReactionInsight[]>([]);

const handleAdvisorExecute = async (insightId: string) => {
  // ... validation, modal check ...
  setActionStates((prev) => ({ ...prev, [insightId]: "loading" }));
  try {
    await someMutation.mutateAsync(action.params);
    setActionStates((prev) => ({ ...prev, [insightId]: "done" }));
    // ── Reaction System ──
    setReactions((prev) => [...prev, generateReactionInsight(action, insightId)]);
  } catch {
    setActionStates((prev) => ({ ...prev, [insightId]: "error" }));
  }
};
```

**Ejemplo de código — Banner:**
```typescript
import type { AdvisorReactionInsight } from "@/features/dashboard/types";
import { AdvisorReactionCard } from "@/shared/components/ui/AdvisorReactionCard";

// En props:
reactions?: AdvisorReactionInsight[];

// En render (antes de los layers):
{reactions.length > 0 && (
  <div className="space-y-2">
    {reactions.slice().reverse().map((reaction) => (
      <AdvisorReactionCard key={reaction.id} reaction={reaction} />
    ))}
  </div>
)}
```

**Domain templates (8):** finance, events, security, governance, wellness, members, communications, commercial. Cada uno con `sourceAction` pattern, `reaction` template con `{metric}` placeholder, `estimatedImpact` range, `confidence` range, `nextStep` text.

**Se replica en:** Fase 23 (Adaptive Thresholds), Fase 24+ (cualquier nuevo dominio de Advisor).

### Patrón: Predictive Pre-fetch (F22c)

**Concepto:** Para roles ADMIN/JUNTA, pre-fetchear automáticamente los narratives de los top-3 insights por severidad al montar cualquier banner. El usuario clickea "Análisis Profundo" → renderiza desde cache de TanStack Query → 0ms latencia percibida.

**Implementación:**
```typescript
export function usePrefetchTopNarratives(
  insights: PrefetchableInsight[],
  financialContext?: Record<string, unknown> | null,
  eventsContext?: Record<string, unknown> | null,
) {
  const queryClient = useQueryClient();
  const userRole = useAuthStore((s) => s.user?.role?.toLowerCase() ?? "socio");

  useEffect(() => {
    if (userRole !== "admin" && userRole !== "junta") return;
    // Sort by impact desc, confidence desc, take top 3
    // queryClient.prefetchQuery() for each
    // staleTime: 600_000 (10min)
  }, [insights.length, userRole]);
}
```

**Se replica en:** Cualquier componente que consuma AI narratives (F23+, AdvisorChatWidget).

## 4. DECISIONES DE DISEÑO

| # | Decisión | Alternativa descartada | Razón |
|---|----------|----------------------|-------|
| 1 | **Reaction System como state local del shell** (no en store global) | Zustand store compartido | Reactions son ephemeral por sesión de dashboard. No necesitan persistencia cross-page. Más simple, menos acoplamiento. |
| 2 | **`generateReactionInsight` como función pura** (no hook) | Custom hook `useReactionInsight` | No necesita lifecycle de React. Es un mapper puro: action → reaction. Más testable, más reusable. |
| 3 | **AdvisorReactionCard en `shared/components/ui/`** | Duplicar en cada banner | 3 banners lo necesitan. Patrón del proyecto: componentes compartidos van en shared. |
| 4 | **Predictive Pre-fetch via `queryClient.prefetchQuery`** | Auto-expand narratives on mount | Mantener UX limpia: banner no se expande automáticamente. El valor es latencia 0ms al click, no mostrar todo de una. |
| 5 | **Pre-fetch solo para ADMIN/JUNTA** | Pre-fetch para todos los roles | SOCIO/STAFF no necesitan deep narratives. Ahorra API calls innecesarios. |
| 6 | **5 sub-componentes finance como triggers on-demand** (no como tabs) | Nuevo tab "Herramientas Avanzadas" | Ya hay 8 tabs. Los 5 sub-componentes son herramientas especializadas, no vistas permanentes. Patrón de "Avanzado:" row con botones ghost es más limpio. |
| 7 | **`executedAction` capture antes de `setModalInsight(null)`** | Dejar que reaction se genere con `modalInsight.action` | BUG: `setModalInsight(null)` limpia el state antes de que la reaction pueda acceder al action. Capture previo es necesario. |
| 8 | **Hook `usePrefetchTopNarratives` en `useAdvisorNarrative.ts`** | Archivo separado `usePrefetchTopNarratives.ts` | Cohesión: ambos hooks manejan la misma concern (narrative fetching). Un archivo, una concern. |
| 9 | **10min staleTime para pre-fetch** | 5min o 30min | Balance: narratives son costosos de generar pero el Advisor puede cambiar entre refreshes. 10min es sweet spot. |
