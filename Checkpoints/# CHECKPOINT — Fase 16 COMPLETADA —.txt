## 6. DECISIONES DE DISEÑO

| Decisión | Alternativa descartada | Razón |
|----------|----------------------|-------|
| Transform helpers en types.ts | Cambiar interfaces de sub-componentes | Sub-componentes están bien construidos. Transform layer es separación limpia |
| RevenueChart → BarChart horizontal | Mantener AreaChart con mock time series | Datos reales son top_revenue_sources. BarChart es más útil |
| YoY visible pero disabled | Ocultar completamente | UX: usuario ve que existe. Cuando backend provea data, solo hay que pasar prop |
| Advisor como CTA expandible inline | Sub-page separada | Patrón consistente con anomalies y age balance. Un solo dashboard scroll |
| Financial + Membership como sub-pages navegables | Secciones on-demand inline | Piden que sean sub-páginas (decisión del usuario). Complejidad de datos merece página dedicada |
| 2 queries (summary + anomaly/age balance) | 3-4 queries auto-load | Summary ya incluye membership, financial, operational, engagement. Solo anomalies y age balance necesitan tools separadas |
| Eliminar get_operational_pulse del componente | Mantener como segunda query | Summary ya tiene operational data. Query redundante |
