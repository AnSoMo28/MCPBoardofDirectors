**Regla de oro (INVIOLABLE):** Yo propongo y analizo ANTES de escribir código. El usuario aprueba antes de generar. Changelog detallado al final de cada bloque. Formato de edición: Bloque A (código actual exacto) → Bloque B (líneas nuevas para copiar y pegar). Nunca mezclar. Siempre cuestiono lo que propongo — el cuestionamiento va dirigido a la mejora.

**Postura operativa:** Ver bug → auditar patrón. Ver tool sin UI → proponer integración. Recibir componente → analizar contra 22+ reglas. Proponer feature → algo que el usuario no sabía que necesitaba. Integrar AI → Intelligence Engine de 5 niveles. Documentar → changelog detallado + verificación.

### REGLA DE FORMATO:

1. **BLOQUE A** = líneas EXACTAS que se reemplazan (copiar del archivo actual)
2. **BLOQUE B** = líneas NUEVAS que las reemplazan (copiar y pegar)
3. **Si es INSERTAR**: "después de X, antes de Y" con líneas literales de referencia
4. **NUNCA** "agregar X al existente" — siempre reemplazar el bloque completo
5. **NUNCA** instrucciones conceptuales — siempre código exacto
6. **Si es REWRITE (>30%)**: entregar el archivo completo
7. **Trabajar por APPENDS** en archivos grandes (factories.ts, contracts.ts, mock-registry.ts)
8. **Nunca proponer bloques sin leer el código primero** — proceso mental paso 1

## 4. PATRONES ESTABLECIDOS / ACTUALIZADOS

### Patrón NUEVO: Backend Tool Migration (F26)

**Concepto:** Workflow completo para migrar una tool de mock-only a backend real.

**10 pasos:**
1. Auditar agent actual (pattern de tools, return shape, decorators)
2. Auditar models existentes (Pydantic pattern, enums, ConfigDict)
3. Auditar repo (métodos CRUD + compute existentes)
4. Auditar mock factory (shape como source of truth para nuevos models)
5. Auditar executive dashboard (verificar si ya existe con otro nombre — Paradigma 1 vs 2)
6. Crear Pydantic models nuevos si necesario
7. Crear repo methods nuevos si necesario (compute inline o en agent según patrón del dominio)
8. Crear MCPTool en agent como thin wrapper (o con compute inline para finance)
9. Alinear mock factory + contracts con nuevos models
10. Verificar registry entry (sin duplicados, sin imports huérfanos)

**Cuándo se aplica:** Cualquier tool mock-only que necesita backend real.
**Archivos donde se aplicó:** wellness (5 tools), finance (1 tool)

### Patrón NUEVO: Dual Paradigma Architecture (F26)

**Concepto:** Dos paradigmas coexisten en el backend.

```
Paradigma 1 (Executive): Hardcoded demo data → siempre muestra algo → F29 migration
Paradigma 2 (Domain): Computed from repo → producción real → F26 migration
```

**Regla:** No confundir tools entre paradigmas. `get_financial_overview` (P1) ≠ `get_financial_summary` (P2).

### Patrón NUEVO: Cross-Domain Correlation Engine (F26b)

**Concepto:** Correlaciones cross-domain calculadas con Pearson sobre engagement score como proxy unificador.

**Algoritmo:** `_pearson(engagement[], metric[])` → coefficient + significance (high ≥0.7, medium ≥0.4, low <0.4)

**Proxies sin datos cross-agent reales:**
- Retention = activity in last 14 days (1.0/0.0)
- Revenue = total_minutes / 100
- Satisfaction = goal_completion_rate / 100
- Spend = 50K + (engagement/100) × 150K CRC
- NPS = max(0, engagement - 10)

**Cuándo se aplica:** Cuando se necesita análisis cross-domain sin acceso real a otros agentes.

### Patrón NUEVO: Aggregated Insights Pattern (F26b)

**Concepto:** Un tool que agrega los outputs de otros tools del mismo agent en un reporte estructurado.

**Implementación:** `compute_insights()` llama `compute_prediction()` + `detect_anomalies()` + `generate_report()` + goals + profile → `WellnessInsightsResponse`.

**Análogo en finance:** `generate_ai_analysis()` agrega 9 dimensiones desde `get_budget()` + `generate_report()`.

### Patrón ACTUALIZADO: Mock Conventions

**Convenciones confirmadas:**
- Factory prefix: `createMock` (no `create`) — `createWellnessReport` es legacy exception
- Factory params: `params?: { key?: type }` — optional, con defaults
- Contract naming: `{tool_name}_Contract` o `{ResponseName}` interface
- Registry entry: `(params) => createMockXxx(params)`
- Append strategy para archivos grandes
- Verificar imports huérfanos después de cada append
