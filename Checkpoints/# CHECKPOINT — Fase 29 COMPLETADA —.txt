## 4. PATRONES ESTABLECIDOS / ACTUALIZADOS

### Patrón NUEVO: Family Advisor Hook (F29)

**Concepto:** Client-side intelligence hook que computa 25 reglas en 5 capas sobre datos del perfil familiar + cross-domain. 0ms latencia, 0 tokens AI, 0 API calls.

**Niveles:**
```
Nivel 1: useFamilyAdvisor(family, activity, financial, social, preferences) → basic insights
Nivel 2: + eventAttendance, communicationEngagement, wellnessUsage → cross-domain insights
Nivel 3: Insights drive AdvisorBanner → user actions → tab navigation
```

**Cuándo se aplica:** Cada dominio que tiene su propio Advisor (Finance ya tiene 18 rules, Communication tiene 8+).
**Fases futuras donde se replica:** Wellness, Events, Engagement como dominios independientes.
**Archivos donde ya está implementado:** `useFamilyAdvisor.ts`, `FamilyAdvisorBanner.tsx`

### Patrón NUEVO: On-Demand Intelligence Sections (F29)

**Concepto:** IntelligencePanel sections que empiezan deshabilitadas y solo cargan datos cuando el usuario hace click. Cada section tiene su propio `useState(false)` para `enabled`.

**Cuándo se aplica:** Para tools de inteligencia que son costosas o que el usuario no siempre necesita.
**Archivos:** `FamilyIntelligencePanel.tsx` (6 sections, todas on-demand excepto las 4 originales que ya existían)

## 6. DECISIONES DE DISEÑO

| # | Decisión | Alternativa descartada | Razón | Impacto |
|---|---------|----------------------|-------|---------|
| 1 | 25 rules × 5 layers para Family Advisor | 8-18 rules como otros dominios | Families es cross-domain — toca todos los dominios del club. La complejidad justifica el nivel. | Otros Advisors no necesitan este nivel. No usar como benchmark para Wellness/Events. |
| 2 | Cross-domain params opcionales (null default) | Requerir siempre los 3 params cross-domain | Los endpoints de Events/Comms/Wellness aún no exponen los summary types. Los params son opcionales con fallbacks inteligentes. | Cuando se conecten los endpoints, se pasa la data y las rules mejoran automáticamente. |
| 3 | Server name `family_profile` (nuevo) | Mantener `families` (legacy) | Backend real usa `family_profile` como server name. Alinear es más importante que backward compat. | Rompe temporalmente hasta que todos los archivos se actualicen. |
| 4 | Hooks calculan en client-side (0ms, 0 tokens) | Hacer todo en backend con AI | Las 25 rules son deterministic logic. No necesitan AI. El hook corre en useMemo. AI solo para narratives on-demand. | 0 costo de tokens para Advisor. AI solo cuando usuario pide "análisis profundo". |
| 5 | On-demand intelligence sections | Cargar todas las sections al montar | 6 sections AI simultáneas = 6 API calls al backend. On-demand = solo las que el usuario necesita. | Mejor performance, menos carga al backend. |
| 6 | Tokens Silver Tide reales vs tokens fantasma propuestos | Usar `--color-text-primary` etc. | Los tokens propuestos NO EXISTEN en globals.css. Habrían roto la UI silenciosamente. | **CRÍTICO:** grep global post-F33 para verificar que no hayan quedado instancias. |
| 7 | `identify_social_clusters` como tool #17 | Dejarla para otra fase | La visión original pedía 17 tools. Sin esta, el cross-family intelligence no tiene backend. | Mock creado, backend pendiente. |
