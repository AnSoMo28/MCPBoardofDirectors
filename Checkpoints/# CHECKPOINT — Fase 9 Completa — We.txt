### Patrón de Implementación AI (NUEVO — importante para futuras fases)

El patrón que establecimos en WellnessAI es **el estándar para todas las fases futuras**:

```
1. Datos (auto-load)    → useMCPQuery con staleTime
2. Inteligencia (on-demand) → useMCPQuery con enabled: shouldFetch
3. Two-phase cuando hay análisis pesado → trigger separado para insights y predictions
4. AIDecisionPanel      → se reutiliza como wrapper (scope: "wellness")
5. Contracts como source of truth → nunca se borran
```

## ARQUITECTURA DE INTELIGENCIA ARTIFICIAL (PATRÓN ESTABLECIDO)

En Fase 9 establecimos un patrón de AI que debes seguir en TODAS las fases futuras:

### El Patrón de 3 Niveles:

**Nivel 1 — Datos (auto-load):** Queries MCP que se cargan automáticamente con staleTime.
```typescript
const { data } = useMCPQuery('server', 'tool', params, { staleTime: 60_000 });
```

**Nivel 2 — Inteligencia (on-demand):** Queries MCP que requieren botón "Ejecutar".
```typescript
const [shouldFetch, setShouldFetch] = useState(false);
const { data } = useMCPQuery('server', 'tool', params, { enabled: shouldFetch });
// Botón: <Button onClick={() => setShouldFetch(true)}>Ejecutar Análisis</Button>
```

**Nivel 3 — Two-phase on-demand:** Cuando hay análisis pesado, separar en dos triggers.
```typescript
const [insightsTriggered, setInsightsTriggered] = useState(false);
const [predictionsTriggered, setPredictionsTriggered] = useState(false);
// Fase 1: Insights (botón principal)
// Fase 2: Predictions (botón separado dentro del componente)
```

### Las 4 Herramientas de Inteligencia (mockeadas, backend pendiente):

Estas 4 tools NO existen en el backend aún. Se mockean con datos realistas:

1. **`wellness_predict`** — Predicción de engagement 30/60/90 días con risk_factors y recommended_interventions

### Wellness Score Engine (implementado en types.ts):

```
Composite = Activity(30%) + Consistency(25%) + Variety(15%) + Social(15%) + Trend(15%)

Activity    = min(100, total_activities / 12 × 100)     // 12/month target
Consistency = min(100, streak_days / 14 × 100)          // 14-day benchmark
Variety     = min(100, unique_types / 6 × 100)          // 6 types max
Social      = social_count / total_count × 100          // group activities ratio
Trend       = current / previous × 50                   // 50 = neutral
```

## 12B. PATRÓN DE IMPLEMENTACIÓN AI (Estándar desde Fase 9)

### Niveles de Carga de Datos:

| Nivel | Patrón | Ejemplo |
|-------|--------|---------|
| 1. Datos (auto-load) | useMCPQuery con staleTime | wellness_report, wellness_profile_get |
| 2. Inteligencia (on-demand) | useMCPQuery con enabled: shouldFetch | wellness_anomalies, wellness_correlate |
| 3. Two-phase (on-demand doble) | Dos triggers separados | wellness_insights (fase 1) + wellness_predict (fase 2) |

### Herramientas de Inteligencia (mockeadas, backend pendiente):

Cada módulo puede tener hasta 4 tools de inteligencia:
1. `{module}_predict` — Predicciones a 30/60/90 días
2. `{module}_anomalies` — Detección de patrones anómalos
3. `{module}_correlate` — Correlaciones con métricas de negocio
4. `{module}_insights` — Motor de decisiones con executive_summary, key_findings, critical_insights

Backend NO implementa estas tools aún. Se mockean con datos realistas. Cuando el backend las implemente, solo se quitan del registry.

### Contracts como Source of Truth:

Los contracts en shared/mocks/contracts.ts definen el shape de TODA tool response.
NUNCA se borran — son la documentación viva de la API.
Los componentes dependen del shape del contract, NO del backend directamente.
